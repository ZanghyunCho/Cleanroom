# SC-P7500 USB 공개키 읽기 시험 GUI

Windows 10/11에서 USB로 연결된 Epson 프린터를 검색하고, SC-P7500의 USB ID·NVRAM 시리얼과 두 후보 위치의 데이터를 읽어 공개키와 비교하는 Python GUI입니다.

## 실행

1. ZIP을 폴더에 풀고 **Python 3.10 이상**을 설치합니다. Windows용 Python의 기본 Tkinter가 필요하며 pip 패키지는 필요하지 않습니다.
2. `run_gui.bat`을 실행합니다. 또는 이 폴더에서 `py -3 app.py`를 실행합니다.
3. **통신 DLL**에서 기존 ServiceSupportTool 폴더의 `EprisDrv.dll`을 선택합니다. DLL은 원래 폴더에 둡니다. 이 ZIP에는 Epson DLL을 재배포하지 않습니다.
4. **USB 검색** → SC-P7500 선택 → 기본 선택 영역 **A3**에서 **두 위치 읽기 시험**을 누릅니다.

`GUI 데모`는 프린터 없이 화면과 결과 저장을 확인합니다. 데모 결과에는 `DEMO_SYNTHETIC`이 표시되며 실기 성공으로 판정하지 않습니다.

## v0.2의 변경

- **USB ID와 NVRAM 시리얼을 별도로 표시**합니다. 두 식별자의 값이 다르다는 이유로 오류를 발생시키지 않습니다.
- 결과 표에 실제 추출 데이터 양을 표시하고, 전체 `FF`·전체 `00`·공개키·일반 데이터·`NA`를 구분합니다.
- **수신 HEX 보기** 또는 결과 행 더블클릭으로 실제 데이터, 회차별 요청 HEX, 원시 응답과 연결 단계를 확인합니다.
- **JSON 열기**로 v0.1·v0.2의 기존 결과를 재분석할 수 있습니다. 원본 로그 파일은 변경하지 않습니다. 이 기능은 USB를 새로 읽지 않습니다.
- 연결 단계와 읽기 호출 직전의 기록을 실시간으로 표시합니다. 시간 초과가 발생해도 이전에 수신한 기록과 유효한 한 회차 데이터까지 보존합니다.

## 무엇을 읽는가

- USB 프린터 인터페이스, 장치 모델, IEEE-1284 정보와 USB ID를 표시합니다. USB ID는 NVRAM 시리얼과 별개의 식별자입니다.
- 서비스 도구와 같은 일반 NVRAM 읽기로 `0x0644`의 시리얼 10바이트를 추가 조회합니다.
- 선택 영역 **A3**의 후보 오프셋 `0x7010`, `0x6D000`에서 **각각 64바이트를 두 번** 읽습니다.
- 필요하면 영역을 **D6**로 선택해 별도 시험할 수 있습니다. 결과 파일에 영역을 기록합니다.

**두 오프셋은 결합 플래시 덤프에서 공개키를 찾은 위치입니다. A3/D6의 서비스 주소 공간과 실제 플래시 주소가 같다는 점은 아직 확인되지 않았습니다.** 프로그램의 목적은 이 가설을 읽기 응답으로 시험하는 것입니다. 오류 또는 `NA`가 오면 해당 결과와 응답 원문을 저장합니다.

기본 참조 파일 `reference/epson-p7500-original-public.bin`은 이전 P7500 원본 덤프에서 추출한 64바이트 Epson 공개키입니다. SHA-256:

```
32c269b3944bebfdb0eacf3b8637d904d658383aa61c2c6b41ee8e8d45251161
```

다른 참조 공개키는 64바이트 `X||Y`, 또는 65바이트 `04||X||Y` 원시 바이너리로 선택할 수 있습니다. 개인키 파일은 필요하지 않습니다.

## 판정

각 위치에서 다음을 확인합니다.

- USB 전송 결과와 실제 생성된 요청이 예정된 읽기 명령과 일치하는가.
- 응답에 요청 길이의 바이너리 데이터와 `; 0C` 종료 표식이 있는가.
- 독립적인 두 읽기에서 64바이트가 같은가.
- 데이터가 P-256 곡선 위의 공개키 형식인가.
- 참조 공개키와 **64바이트 전체가 정확히 일치하는가**.

모델·NVRAM 시리얼 확인과 두 위치의 반복 읽기·참조 비교가 모두 충족되면 일치 결과를 표시합니다. USB ID와 NVRAM 시리얼의 동일성은 검사하지 않습니다. 불일치 데이터와 `FF` 데이터도 원문과 함께 저장합니다. `NA`는 데이터가 없는 응답으로 표시합니다. `FF`만 수신했다고 실제 플래시가 지워져 있다고 단정하지 않습니다. 키가 일치하더라도 해당 주소의 물리 플래시 매핑과 쓰기 가능성까지 증명한 것은 아닙니다.

## 결과 파일

기본 폴더: `%USERPROFILE%\Documents\P7500_USB_probe_results`.

- 시간별 `.json`: 모델, USB ID, NVRAM 시리얼, 영역, 예정된 요청과 실제 호출·반환 기록, 응답 캡처 창, 판정, 오류, SHA-256.
- 각 위치와 회차별 `.bin`: 형식 검사를 통과해 추출한 64바이트. 한 회차만 반환된 경우에도 그 데이터를 보존합니다.
- USB DLL은 수신 길이를 호출자에게 반환하지 않으므로 응답은 **0으로 초기화한 버퍼의 앞 4096바이트 캡처 창**으로 저장합니다. 실제 데이터 길이가 4096바이트라는 뜻은 아닙니다. 데이터 추출은 요청 길이와 종료 표식으로 검증합니다.

로그와 시리얼은 지정한 PC 폴더에 저장됩니다. 네트워크 전송 기능은 없습니다.

## USB 통신 방식

GUI는 일반 64비트 Python에서도 실행됩니다. 포함된 `bin/usb_bridge32.exe`가 별도 프로세스로 32비트 Epson `EprisDrv.dll`을 호출합니다. 따라서 서비스 도구와 같은 Epson USB 드라이버를 사용할 수 있으며 WinUSB 교체가 필요하지 않습니다.

분석한 DLL만 허용합니다. SHA-256:

```
42f775bdd44425227a36750d6942104db99c9a37dfe82c4ce2d810b7b38eda18
```

읽기 세션의 저장 영역 명령은 `98/67/4C`, 시리얼 조회 명령은 `5D/A2/AE`입니다. 주소와 크기는 보조 프로그램에도 고정되어 있습니다. 저장 쓰기·준비·완료 명령 `97/99/9A`를 전송하는 기능은 없습니다. USB 채널 열기·닫기와 읽기 요청의 전송은 통신 DLL이 처리합니다.

## 연결 문제

- **Epson 프린터가 검색되지 않음:** USB 케이블과 기존 Epson 드라이버를 확인하고 다시 검색합니다. 네트워크 프린터는 대상에 포함하지 않습니다.
- **장치 ID 또는 USB Open 실패:** 다른 서비스 도구·프린터 모니터가 장치를 점유했는지 확인합니다. 오류 코드는 결과에 남습니다.
- **LoadLibrary 오류 126:** 해당 서비스 도구의 DLL 종속성이 부족할 수 있습니다. 서비스 도구가 사용하는 **Visual C++ 2015–2022 Redistributable x86**와 MFC 런타임이 필요합니다. GUI Python의 비트 수와 별개입니다.
- **DLL 해시 불일치:** 첨부해 준 서비스 도구에 포함된 원본 `EprisDrv.dll`을 선택해야 합니다.
- **NA·시간 초과·참조 불일치:** 실패를 그대로 기록합니다. 지원 모드·저장 영역·주소 대응에 관한 분석 자료입니다. 첨부 매뉴얼의 NVRAM 작업 모드는 서비스맨 모드로 설명돼 있습니다. 이 프로그램은 프린터 모드를 자동 변경하지 않습니다.

## 검증 범위

이 개발 환경에서 Python 단위 시험 28개를 통과했고, 실제 보조 프로그램과 공유하는 C 패킷 생성 코드도 컴파일해 검사했습니다. 원본 서비스 DLL을 격리 실행해 얻은 두 읽기 프레임과도 바이트 단위로 일치함을 확인했습니다. 보조 프로그램은 Windows x86 PE로 교차 빌드했습니다. **이 환경에는 연결된 P7500과 Windows가 없어 실제 USB 통신 및 Windows GUI 실행은 아직 검증하지 못했습니다.**

시험 실행:

```
python -m unittest discover -s tests -v
```

네이티브 소스는 `native/usb_bridge.c`, 고정 읽기 패킷 코드는 `native/read_packets.h`입니다. 재빌드가 필요한 경우 Zig 0.13을 PATH에 추가한 명령 프롬프트에서 `native\build_bridge.bat`을 실행합니다. 일반 사용에는 포함된 EXE를 사용하면 됩니다.
