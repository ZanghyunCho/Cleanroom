# SC-P5380 / KU25Q4 R4.7 — R4.6B + 잉크 덮개·제조사·정품 표시·LOONA

사용자는 R4.6B가 정상 동작한다고 보고했다. R4.7은 이 후보를 기준으로 요청한 기능을 결합한다. R4.6A에서 오류 308223이 재현됐던 전역 사용량 getter 0 처리는 포함하지 않는다. 원래 getter 및 R4.6B의 국소 소비 전 검사 변경을 보존한다.

## 변경 범위

- 좌·우 잉크 카트리지 덮개의 상태 ID 0x6009/0x600a/0x602f/0x6030과 두 슬롯의 캐시 및 해당 열림 콜백을 닫힘으로 처리한다. 원본 분류에서 두 덮개 type 2/3은 인터록 플래그가 0임을 확인했다. 별도 인터록 분류·판정·비상 정지 및 유지보수 덮개 함수는 바이트 단위로 유지한다.
- 공통 카트리지 문자열 필드 조회에서 제조사 항목 2는 EPSON을 반환한다. 다른 문자열 필드는 원본 처리다.
- 공통 비정품 표시 플래그 getter/setter는 원본 setter를 사용해 0을 기록·반환한다. 이 플래그와 실제 칩의 모든 암호 인증 결과를 동일시하지 않는다. 암호 검증 함수 자체는 변경하지 않았다.
- 품번은 원본 NVRAM 키 0x261의 제품 프로필 및 색상 역할별 품번 조회 경로를 보존한다. T55Y로 강제 고정하지 않는다. 이전 원본 ARM 시험에서 네 프로필의 T55V/T55W/SC33/T55Y 각 10종, 총 40개 선택을 확인했다. 현재 기기 NVRAM을 읽거나 변경한 것은 아니다.
- LOONA 부트로고는 기존 공개된 S2-LOONA에서 로고 리소스만 가져왔다. S2의 실행 코드를 가져오지 않았다. 최종 로고 리소스 해시 및 슬롯 바이트가 기존 LOONA와 일치한다.

## 검증과 미확인 범위

최종 EFU에서 실행 코드를 다시 추출해 5,752개 시험을 통과했다. R4.6B 회귀, 소비 전 비교, 전역 getter 원본 반환 보존, 좌우 덮개 및 다른 덮개/인터록 비교, EPSON 제조사 및 비정품 표시 플래그 시험을 포함한다. 별도로 같은 실행 모듈 해시에서 제조사 이외 문자열 필드 160개 사례가 기준 코드와 같은 결과·칩 읽기 요청을 유지하는지 확인했다. 물리 칩 읽기·DSM IPC·상태/모드 등은 명시된 fixture다.

ZIP CRC·재추출, 섹션 합계·SHA-1·경계, 코드 압축 복원 일치, 두 번째 CROM 프레임 및 허용 영역 밖 바이트 보존을 확인했다. LOONA 리소스의 복원 해시는 7911319cc1eab60d50b123a4cd430991d67f0591f9a112ef5b122a9c47e0cd78이다.

본체·PC·웹 모든 화면에서 요구 품번·EPSON·정품 표시가 항상 동일하게 나타나는지 끝까지 실기 확인하지 않았다. 품번 조회 함수 자체를 별도 강제 문자열 반환으로 바꾼 후보도 아니다. 실제 칩이 없는 동작은 구현 완료로 주장하지 않는다. R4.5의 제조사/표시 변경은 R4.6B와 별도로 실기 통과가 입증되지 않았으므로 본 결합 후보는 다시 실기 확인이 필요하다.

원래 공개키·서명 바이트는 유지하지만 수정된 본문에 서명은 유효하지 않다. 선언 길이 실제+1 방식은 이전 후보와 같다.

## 실기 비교

R4.6B와 같은 카트리지·칩 조건에서 부팅·인쇄 및 308223 재발 여부를 먼저 확인한다. 그 다음 좌우 잉크 덮개를 각각 열었을 때의 상태와 본체·PC·웹의 각 슬롯 품번·제조사·정품 표시를 구분해 기록한다. LOONA 로고도 전원 켜기 시 확인한다. 문제가 생기면 정상 보고된 R4.6B를 복귀 기준으로 사용한다. 현재 R4.7 자체의 실제 부팅·인쇄·도어 상태 결과는 없다.
