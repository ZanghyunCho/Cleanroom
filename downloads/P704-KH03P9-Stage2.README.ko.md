# P704 Stage 2: 모든 잉크 카트리지의 잔량 100% / 소프트웨어 사용량 0

**후속 결함 확인:** 이 구 버전의 유지보수 필드 0x49/0x4b 고정은 원본 기록 검증과 충돌합니다. 반복 동기화 오류를 재현했으며, [Stage 2 R1 수정본](P704-KH03P9-Stage2-R1.README.ko.md)에서 해당 명령 세 개를 원복했습니다. 아래 내용과 시험 결과는 생성 당시 기록입니다.

기준은 P704 공식 FW4838TL.efu의 KH03P9.FY19입니다. 사용자가 실기 통과를 보고한 P704 Stage 1의 유지보수 변경을 모두 유지하고, 잉크 카트리지 10개 슬롯의 회계·잔량 보고 경로를 추가 수정했습니다. Stage 2 자체의 실기 결과는 아직 없습니다.

## 변경

- 원본의 슬롯별 ID 매핑을 보존합니다. 기본 사용량 ID는 0x1296, 0x1297, 0x1299, 0x129b, 0x1309..0x130e입니다. 보조 동기화 사용량 ID는 0x1004, 0x1005, 0x100a, 0x1098..0x109e입니다.
- 이 ID들의 공통 설정 읽기 때 실제 RAM 누적값을 0으로 지우고 0을 반환합니다. 공통 쓰기도 0만 기록합니다. 슬롯별 함수 이외의 공통 저장 경로로 들어오는 요청에도 적용합니다. 다른 설정 ID와 호출자의 입력 버퍼는 보존합니다.
- 기존 32비트 setter의 값 비교·변경 여부 반환은 그대로 실행합니다. 이미 0이면 변경 없음, 기존 값이 비영이면 0 기록에 대한 변경 있음을 반환합니다. 읽기 중 RAM 정규화가 물리 NVRAM 쓰기 완료를 의미하지는 않습니다.
- 펄스 누적값과 정규화된 사용량 캐시도 읽기·설정·증가 때 해당 슬롯을 0으로 처리합니다. 칩 사용량 접근은 원래 슬롯 선택과 필드 접근을 실행하면서 읽기 결과와 두 복사본에 쓸 사용량을 0으로 정규화합니다. 실제 칩이 그 쓰기를 수락했는지는 실기 확인 대상입니다.
- 공통 잉크 잔량 이벤트의 숫자 값을 100으로 저장하고, 정상 숫자 잔량 getter도 100을 반환합니다. 0~100 숫자 잔량과 미장착·통신·호환성 등 별도 상태 인코딩을 구분합니다. 원래 상태·정품 인증·비정품 사용 승인·커버 처리는 유지합니다. 별도 오류 상태를 무조건 숫자 100으로 덮는 변경은 아닙니다.
- Stage 1의 유지보수 사용량·잔량 변경 29개 명령은 바이트 그대로 보존했습니다.

새 코드는 기존 잉크 getter/setter 함수 영역 안에 배치했습니다. 원본에서 다른 함수가 그 내부 블록으로 진입하지 않음을 확인했고, 새 실행 영역을 BSS나 인접 모듈에 추가하지 않았습니다. 원래 10개 슬롯의 매핑과 범위를 벗어난 슬롯 처리도 보존했습니다. Stage 1 대비 바뀐 실제 코드 바이트는 412개입니다.

## 최종 EFU 검사

최종 파일에서 다시 추출한 실행 코드가 1,295개 시험을 수행한 모듈과 정확히 일치합니다. ZIP CRC, 섹션 3개의 메타데이터·본문 합계, SHA-1과 섹션 경계를 확인했습니다. 원본 Huffman 테이블로 재압축했고 패딩은 3개, DMA 출력 크기는 48바이트 배수입니다. 후속 두 번째 프레임의 바이트와 복원 결과를 보존했습니다.

원본 첫째·둘째 섹션 본문, Epson 공개키와 서명 바이트를 유지했습니다. 선언 본문 길이는 실제 +1입니다. 변경된 본문에 원래 서명이 유효한 것은 아니며, 일반 ECDSA 검증은 예상대로 실패합니다. ECDSA 판정 성공 패치는 없습니다.

## 실기 범위

Stage 1 통과는 사용자 보고입니다. Stage 2의 업데이트·부팅·인쇄·재부팅 후 복원과 실제 잉크 칩/EEPROM 기록은 미검증입니다. 소프트웨어가 보는 회계값을 고정하는 수정이며 실제 잉크를 보충하거나 물리 칩의 모든 누적 셀을 소거하는 도구는 아닙니다. 카트리지 미장착 운전이나 별도 인증/비호환 오류의 무조건 해제도 포함하지 않습니다.

장착 상태에서 10개 색상의 잔량, 출력/청소 전후 사용량, 재부팅 후 잔량과 유지보수 Stage 1 동작을 비교해 확인합니다.

## 재현

검증 ZIP의 디렉터리 구조를 /workspace/p704-analysis에 복원하고 원본 FW4838TL.efu/RCX 및 decoded/0x4f0a12e.bin을 준비합니다. CROM 디코더는 prior/decode_crom.py의 decode(rcx, 0x4f0a12e)입니다. Python 의존성은 unicorn, keystone-engine, cryptography입니다.

    /workspace/cleanroom-tools/bin/python stage2/verify_stage2.py
    /workspace/cleanroom-tools/bin/python stage2/build_stage2.py

검증 ZIP에는 빌드·시험 코드, 수정 모듈, 변경 위치, 시험 결과와 CROM 인코더·디코더가 포함됩니다. 원본 대용량 입력은 중복 포함하지 않습니다.
