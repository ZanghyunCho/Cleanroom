# SC-P5000 N005O6 커버 입력 마스크 — REV2 실험본

**REV1은 실제 장비에서 커버 열림 중 인쇄 명령이 멈추는 문제가 확인됐다. 재사용하지 않는다.**
REV2는 원본에서 새로 만들었으며 실제 장비에서 업데이트/부팅/인쇄를 검증하지 않았다.

## 변경

실행 코드의 차이는 원본 대비 **한 바이트**, 이미지 오프셋 0x12496B의 C0→00이다.
0x10024968 명령의 공통 입력 마스크가 0x3FBEC000에서 0x3FBE0000으로 바뀐다.
입력 읽기 0x10024954의 반환값에서 좌/우 커버의 0x8000/0x4000만 제외한다.
나머지 입력 비트와 실제 입력 레지스터 자체는 바꾸지 않는다.

REV1에서 바꿨던 두 캐시 조회와 네 콜백 처리 구간은 모두 원본으로 복원했다.
입력 디스패처, 디바운스, 콜백 등록, 메시지 수신·송신 코드도 원본과 동일하다.
상위 처리만 닫힘으로 꾸미거나 커버 알림 분기를 강제로 건너뛰는 방식이 아니다.
논리 입력이 계속 닫힘이므로 물리 개폐에 대한 정상적인 교체 알림 발생을 보장하지 않는다.

## 검증

- 원본/수정 입력 포트 읽기의 p-code 실행: 각 비트, 양쪽 조합 및 무작위 입력에서 커버 두 비트만 제거됨.
- 원본 커버 샘플러 함수 실행: 물리 조합과 관계없이 샘플 결과 0.
- 실행 코드 한 바이트 차이 및 실패본의 여섯 구간 원상복구 확인.
- 압축 스트림 재복원 결과가 그 한 바이트 변경과 정확히 일치함.
- 압축 두 구간의 길이 변화 -3/+3을 상쇄해 전체 압축 길이 및 블록 경계를 유지함.
  두 구간 사이의 압축 바이트는 일시적으로 3바이트 이동하며 두 번째 구간 뒤 원래 위치로 복귀한다.
- RCX·EFU 전체 크기와 ZIP 항목 배치 유지. 기타 구성요소/언어 리소스 보존.
- 알려진 가산 체크섬 및 전체 ZIP CRC 확인.

실제 IRQ/RTOS 메시지 대기/인쇄 경로/카트리지 교체 전체는 미검증이다.
p-code 모델은 외부 호출과 호출 규약을 모델링했으며 실제 CPU 실행 환경 전체가 아니다.
하드웨어가 이 소프트웨어 경로 외에서 커버를 검사하는지까지 배제하지 못했다.
따라서 REV1의 멈춤이 해결됐다고 주장하지 않는다.

파일 크기: 9,849,257바이트 (공식 원본과 동일).
SHA-256: 6aee3df02899473907ccf5fae2415d9b0a12cb8efd0cccf6c23c831e90a1dda2

공식 원본 복구 후 시험한다면 먼저 닫힌 상태의 기본 동작을 확인한다.
열린 상태에서 대용량 작업을 보내지 말고 작은 작업으로 관찰한다.
멈춤/이상이 재발하면 반복 명령을 중단하고 해당 모델의 공식 복구 절차를 따른다.
커버 안에 손을 넣은 상태에서는 인쇄하지 않는다.
SC-P10000 등 다른 모델에는 사용하지 않는다.
