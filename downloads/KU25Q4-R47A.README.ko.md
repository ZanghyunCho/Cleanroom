# SC-P5380 / KU25Q4 R4.7A — R4.6B + 좌우 잉크 덮개 + LOONA만

사용자는 R4.6B가 정상 동작하지만 R4.7에서는 전원 켜기 시 308223이 재발했다고 보고했다. R4.7의 어느 추가 변경이 원인인지는 미확정이다. 사용자 요청에 따라 R4.6B를 기준으로 좌우 잉크 카트리지 덮개 처리와 LOONA 로고만 결합했다.

## 포함·보존

- R4.6B의 국소 소비 전 사용량 계산과 원본 전역 사용량 getter를 유지한다.
- 원본 분류에서 인터록 플래그 0인 type 2/3, 좌우 잉크 덮개만 닫힘으로 처리한다. 네 상태 ID, 두 슬롯 캐시, 해당 열림 콜백과 집계 함수에 적용한다.
- 별도 실제 인터록 분류·판정, 비상 정지 및 유지보수 덮개 코드는 변경하지 않는다.
- LOONA는 기존 공개된 S2-LOONA의 로고 리소스만 사용한다. S2 실행 코드는 사용하지 않는다.

R4.7의 제조사 EPSON 강제 반환과 비정품 표시 플래그 변경은 제외했다. 해당 세 진입점과 그 보조 코드를 넣었던 영역이 R4.6B 원본과 같은지 빌드에서 확인한다. 국가 설정, 품번 선택, 칩 통신 및 실제 칩 인증도 이번에 변경하지 않는다.

## 검증

최종 EFU에서 실행 코드와 로고를 다시 추출한다. R4.6B 회귀, 소비 전 검사, 원본 전역 getter 보존, 덮개 상태/캐시/콜백 및 다른 인터록·덮개 보존 시험을 실행한다. 코드가 시험 모듈과 같고 허용한 덮개 변경 영역 외에는 R4.6B와 같은지 확인한다. LOONA 리소스 바이트와 복원 해시가 기존 LOONA와 같은지 확인한다.

ZIP CRC·재추출, 섹션 합계·SHA-1·경계, 두 번째 CROM 프레임 보존과 허용 영역 밖 바이트 보존을 확인한다. 원래 공개키·서명 바이트는 유지하지만 수정된 본문에 서명은 유효하지 않으며 선언 길이 실제+1 방식은 기존 후보와 같다.

이 시험은 실제 전체 부팅·인쇄 또는 물리 센서 시험이 아니다. LOONA가 오류 원인이 아니라는 가설 역시 이번 결합 후보의 실기 통과로 확정되지는 않는다. 실제 오류 원인은 아직 미확정이다.

## 실기 비교

R4.6B와 동일한 카트리지·칩 조건에서 전원을 켜 LOONA 표시와 308223 재발 여부를 먼저 확인한다. 부팅하면 좌·우 잉크 덮개를 각각 열었을 때의 상태와 인쇄를 확인한다. 문제가 생기면 실기 통과한 R4.6B를 복귀 기준으로 사용한다. R4.7 파일과 R4.7A 파일을 구분한다.
