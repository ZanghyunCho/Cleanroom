# LK29Q5 진단용 F1: 원본 칩 생략 분기만 분리 시험

사용자는 E가 매우 정상적으로 동작한다고 보고했습니다. 이는 정상 동작 보고이며,
실제 누적 사용량의 작업 전후 비교로 증가 중단을 확인한 보고는 아닙니다.
다음 목표는 유지보수 카트리지 칩이 없어도 정상 상태로 처리되는 경로입니다.

**F1의 실제 부팅 및 칩 미인식 동작은 미검증입니다. 미장착 완성본으로 표시하지 않습니다.**
먼저 카트리지를 장착한 상태에서 F1이 정상 부팅되는지 확인해야 합니다.
정지하면 미장착 시험을 하지 말고 E 또는 공식 원본으로 되돌립니다.

## E 대비 변경: 코드 1바이트

```
0x4340acf0: mov r0,#0 -> mov r0,#1
```

원본 프로필 조건 함수의 기본 결과만 1로 바꿉니다. 함수의 프로필 기록 읽기와
조건 비교는 유지하며, 호출자들이 원본의 칩 생략 분기를 선택하도록 합니다.
프로필 조건은 초기 상태·장착 조회·칩 읽기/쓰기·용량 설정 등 여러 경로에 영향을
주므로 단순히 장착 여부의 출력 한 바이트만 바꾸는 수정은 아닙니다.

E의 실제 카운터 읽기와 새 사용량 인자 0, D의 수명 처리, C의 수치 잔량 100%를
유지합니다. 공식 원본 대비 실제 코드 차이는 12바이트, 명령 위치는 7곳입니다.
원시 상태 getter와 오류 선택기, 커버 확인은 원본입니다. 모든 상태를 정상으로
반환하거나 카운터 읽기를 0으로 속이지 않습니다.

실패한 v3에도 이 프로필 조건의 변경이 포함됐지만, 당시에는 실제 카운터 읽기와
증가 함수 등도 동시에 바꿨습니다. 이번 F1은 정상 동작이 보고된 E에서 조건 1바이트만
분리한 실험입니다. 따라서 v3의 정지가 다시 발생하지 않는다는 실기 보장은 없습니다.

## ARM 시험 527건

- E 회귀 검사 395건: 기존 값 읽기, 새 사용량 추가 인자 0, 잔량 보고, 수명·다른 오류 처리.
- 초기화/장착 조회/동기화/쓰기/사용량/준비 상태/후속 장착 전이 128조건.
  모델의 칩 장착 유무, 기존 카운터 4종, 분수 잔량 2종, 미러 데이터 2종,
  보정 기록 2조건, 프로필 바이트 2종을 조합합니다.
- F1의 각 결과를 원본 E가 실제로 생략 프로필을 선택한 RAM 참조와 비교합니다.
  F1의 상태 0은 원본 초기화 함수가 설정하며, getter가 정상 상태를 강제 반환하지 않습니다.
- 원본 E의 일반 프로필은 모델에서 칩 부재를 조회하고 거부하는 대조군을 포함합니다.
- 커버 상태 3종과 위 대조군 1건. 커버 상태 출력의 거부가 유지됩니다.

모델의 F1에서는 장착 조회가 1이고 물리 칩 조회 콜백은 0회이며 기존 누적값이
유지됩니다. 유지보수 판정 반환이나 PC를 성공 지점으로 바꾸는 hook은 없습니다.

단, 버스 초기화/종료 콜백은 모델에서 생략했고 OS 지연·신호·복사 유틸리티는
fixture입니다. 프로필·시계·비휘발성 캐시는 합성 입력입니다. 보정 기록은 이미지
기본값 또는 `0x4e=0`, `0x4f=90`을 사용하며 실제 프린터의 값으로 측정한 것이 아닙니다.
실제 버스 동작, 전체 RTOS/상위 UI 시작 완료를 재현한 결과가 아니므로 이 시험이
실기 부팅이나 칩 미인식 성공을 보장하지 않습니다.

## 포장 검사

네 섹션의 합계·내부 SHA-1, ZIP CRC, 시험한 모듈과 압축 해제 바이트 일치 검사를
통과했습니다. 원본 ARM 함수로 첫 섹션 117,047,296바이트 합계 검사 성공(1),
원본 로더의 기술자·DMA·LZ 재구성 검사를 통과했습니다. 실제 하드웨어 Huffman
처리는 완료 경계 모델을 사용했습니다.

원래 Epson 공개키·서명 바이트·최신 수신 모듈을 유지하고 선언 길이는 실제보다
1바이트 큽니다. 일반 ECDSA 서명은 변경 본문에 대해 유효하지 않습니다.
이번 F1 전체 입력의 상위 ARM 수신 함수 재생이나 실제 플래시 작업·부팅을 실행한
결과는 아닙니다.

## 실기 시험 순서

1. 정상 동작하던 카트리지를 장착한 채 F1로 업데이트하고 정상 대기 화면까지 시작하는지 확인합니다.
2. 이 단계에서 멈추면 E로 복구하고 결과를 기록합니다. 칩 미인식 시험은 진행하지 않습니다.
3. 정상 부팅이 확인된 경우에만 실제 폐잉크 수거 구조를 유지한 채 칩 미인식 조건을 시험합니다.
   소프트웨어에서 장착으로 처리해도 실제 폐잉크 발생과 수거 필요성은 사라지지 않습니다.
4. 부팅/대기 화면, 유지보수 장착 표시와 100% 표시, 오류 문구를 각각 기록합니다.

칩의 전기적 인식 여부와 물리적 폐잉크 수거는 별개의 조건입니다. 수거 경로가 없는
상태로 카트리지를 빼고 인쇄하는 시험을 권하는 파일이 아닙니다.
