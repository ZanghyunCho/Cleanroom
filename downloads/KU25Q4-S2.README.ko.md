# SC-P5300 Series / KU25Q4 S2 — 전체 카트리지 잔량·사용량

사용자가 S1 통과를 보고한 뒤 요청한 두 번째 단계입니다. S1의 두 유지보수 슬롯 처리를 보존하고 KU25Q4의 **10개 잉크 슬롯**에 잔량 100%와 확인된 사용량 경로의 0 처리를 추가했습니다. S1 실기 보고를 S2 실기 성공으로 간주하지 않습니다.

## 구현 범위

잉크의 순수 잔량 조회 함수 `0x4462ee88`은 10개 슬롯 모두 100을 반환합니다. 원본 잉크 raw state, 장착 감지, 정품/브랜딩 정보와 승인 프롬프트는 변경하지 않았습니다. 따라서 별도 오류 상태나 비정품 승인 경고까지 없어진다는 의미는 아닙니다.

확인한 잉크 사용량은 32비트 하위 배열과 8비트 상위 배열로 나뉩니다. `(0x22,0x23)`, `(0x24,0x25)`, `(0x30,0x31)` 세 쌍에만 읽기·설정·증가 처리를 적용합니다. 읽기 시 해당 슬롯의 실제 RAM 카운터를 원래 setter로 0으로 지우고 `(0,0)`을 반환합니다. 설정·증가 요청도 원래 setter에 0을 전달합니다. 기존 사용량을 그대로 둔 채 증가분만 막는 방식과 다릅니다. 호출자의 스택 인자 영역은 변경하지 않습니다.

잉크 소수 누적 배열 2개, 추가 사용량 ID `0x33`, 실제 잉크 소비 worker에서 함께 갱신하는 추가 64비트 RAM 누적값도 확인한 조회/소비 경로에서 0 처리합니다. 일치하지 않는 카운터 쌍은 원본 함수 본문으로 진행합니다. ID `0x33`은 유지보수 전용 소수 배열을 사용하지 않는 별도 경로를 사용하므로 잉크 슬롯 번호로 유지보수 RAM을 침범하지 않습니다.

S1의 정상 유지보수 잔량 100%, 사용량·소수 누적값 0 동작을 보존합니다. 잉크 분사·헤드 구동·프린터 모드·커버·기계 제어와 칩 통신은 변경하지 않았습니다. 카트리지 없이 사용하는 기능이나 모든 오류/경고를 해제하는 기능은 포함하지 않습니다.

## 최종 파일에서 추출한 ARM 코드 검증

최종 EFU에서 RCX와 CROM을 다시 추출·복원한 실행 코드로 **7,063개 시나리오**를 통과했습니다. 원본 S1과 S2의 실제 ARM 명령을 실행했고 함수 판정값을 대체하는 훅은 사용하지 않았습니다.

| 검사 | 시나리오 |
|---|---:|
| S1 유지보수 및 다른 ID 회귀 검사 | 1,905 |
| 잉크 10개·유지보수 2개 슬롯 확인 | 1 |
| 잉크 3종 카운터 쌍의 읽기·설정·증가 | 3,240 |
| 일치하지 않는/관련 없는 카운터 쌍 원본 대조 | 360 |
| 잉크 ID 0x33 및 유지보수 RAM 보존 | 270 |
| 10개 잉크 슬롯의 잔량 조회와 raw state 보존 | 750 |
| 추가 RAM 누적값의 조회·설정·증가 | 450 |
| 원본 잉크 전용 소비 helper 대조 | 80 |
| 실제 10슬롯 잉크 소비 worker 대조 | 7 |

S1 회귀에서 ID `0x33`의 기존 18개 일반 ID 검사는 새 잉크 동작을 검증하는 270개 전용 검사로 대체했습니다. 다른 유지보수 검사를 생략한 것이 아닙니다. 실제 worker `0x4461cca8`과 `0x4461cd18`의 원본에서는 양수 잉크 소비 시 카운터 또는 소수 누적값이 증가했고, S2에서는 확인한 값들이 0으로 유지됐습니다. 프로필 0 및 잉크 역할 2~11을 RAM fixture로 초기화했으며 실제 기기 상태를 읽은 것은 아닙니다.

## 포장과 무결성

원래 공개키·서명 바이트를 유지하고 A/B/S1과 같이 선언 본문 길이를 실제 +1로 설정했습니다. 수정된 본문에 대해 기존 서명은 유효하지 않습니다. ECDSA 판정 코드를 성공으로 대체하지 않았습니다.

ZIP CRC·재추출 일치, 내부 2개 섹션의 합계·SHA-1·경계, 허용 범위 밖 바이트 보존을 확인했습니다. 첫 CROM의 최종 복원 코드가 시험 코드와 같고, 두 번째 프레임은 바이트와 복원 결과를 보존합니다. 원래 Huffman 테이블을 사용하고 토큰 패딩·할당 범위를 검증했습니다.

EFU SHA-256: `66bd161b0b9c6fa2da49af0cca8cb412c2840a195f5f658acb45f0b56d292cc8`

최종 복원 실행 모듈 SHA-256: `2c23dd32742e4060cdeb1c9e20a9da49d6d54072094d1e4eb0082826f7661453`

## 실기 확인 범위

**S2의 실제 업데이트·전체 부팅·인쇄·소비 후 잔량 고정은 미검증입니다.** 실제 칩 EEPROM 내용, 재부팅 후 복원 경로, 모든 직접 RAM/DMA 기록까지 검증한 것은 아닙니다. 검증 범위는 식별한 원본 ARM 회계/보고 경로와 최종 EFU 포장입니다.

S1 결과와 비교해 S2 적용 후 잉크 10개 및 유지보수 2개 각각의 잔량을 기록하고, 인쇄·청소 등 실제 소비가 발생하는 동작 전후 및 재부팅 전후에 잔량과 사용량을 비교해야 실기 고정을 확인할 수 있습니다. 오류/경고가 있으면 잔량 숫자와 별도로 그 상태를 기록합니다.
