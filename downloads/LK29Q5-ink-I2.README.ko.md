# I2: 비정품 카트리지 확인 반복 경로 분리

사용자는 I1에서 잔량 100% 표시가 정상적으로 작동하지만, 인쇄할 때마다 EPSON 비정품 경고에 확인을 눌러야 한다고 보고했다. I2는 그 후속 **실기 미검증** 후보다.

## 원인 경로와 변경

I1은 잔량과 알림 표현을 변경했지만, 원본의 비정품 사용 승인 판정을 그대로 두었다. 원본 `AcceptNoLogoInk` 경로는 RPC 명령 `0x23`을 거쳐 `0x43411030`, `0x4340fdb4`로 이어진다. 해당 처리는 슬롯별 승인 레코드 `0x28`을 설정한 뒤 원본 상태 판정을 다시 수행한다.

원본 상태 설정 함수는 정상 상태 후보를 처리할 때 카트리지 메타데이터와 승인 레코드 `0x28`을 확인한다. 미승인 조건에서는 시험 모델에서 선택 오류 `0x43`, 원시 상태 10이 되고, 원래 확인 처리 후에는 `0x40`, 상태 0으로 돌아왔다.

**I2의 추가 변경은 `0x43403cd8`의 명령 한 개뿐이다.** 이 특정 승인 조회의 결과를 1로 처리해 승인 완료 상태와 같은 입력을 제공한다. 일반 OK 처리, 암호 검증 반환값, 모든 오류 getter 또는 전체 승인 비트 읽기 함수를 바꾸지 않는다. 별도 승인 레코드 `0x29`와 기존 선택 오류 0~63의 유지 조건은 그대로다.

실제 카트리지가 정품으로 인증된다는 뜻은 아니다. 비정품 사용 확인 조건을 이미 승인된 것으로 취급하는 변경이다. 다른 비호환/통신/명시적 오류가 자동 해제된다는 보장도 없다.

## 검증

- 기존 I1 경계 시험 1,671건을 I2에서 재실행했다.
- 슬롯 12개 × 입력 상태 코드 70개 × 관련 메타데이터 2종의 조합 × 별도 승인값 2종: 6,720건. I2를 원본 I1에서 승인 레코드 `0x28`을 실제 설정한 대조군과 비교해 선택 오류와 원시 상태가 같음을 확인했다.
- 슬롯 12개 × 기존 선택 오류 0~63: 768건. 해당 오류와 원시 상태가 보존되는지 확인했다.
- 합성 작업 10회를 연속 실행하는 시퀀스 1건. 매회 승인을 0으로 초기화하면 I1은 `0x43/상태10`으로 돌아가지만, I2는 `0x40/상태0`을 유지했다. I1에 원본 확인 처리 함수 `0x4340fdb4`를 실행한 결과와 I2가 일치했다.
- 총 9,160건은 합성 RAM의 ARM 시험이며 실물 인쇄 횟수가 아니다. 실제 UI 표시·USB·전체 부팅·전기적 칩 동작은 실행하지 않았다.
- 최종 EFU 모듈 일치, ZIP CRC, 네 섹션의 합계·SHA-1, 원본 ARM 로더/DMA/LZ 및 본문 합계 검사를 통과했다. 하드웨어 Huffman은 완료 경계에서 모델링했다.

## 유지한 기능과 제한

I1의 100% 잔량 보고와 두 소비 증가 helper 변경, E의 기존 유지보수 변경, 검은 배경 LOONA 로고를 유지한다. G/G2 변경은 포함하지 않는다. 원래 공개키·서명 바이트·수신 모듈과 선언 본문 길이 `실제 + 1`을 유지한다. 수정 본문의 서명이 유효한 것은 아니다. 커버 센서와 한국어 글꼴은 변경하지 않았다.

원본 승인 경로와 일치하는 상태 결과는 확인했지만, 실제 프린터의 해당 경고가 모두 사라지는지는 실기 확인이 필요하다. 다른 경로에서 명시적으로 발생하는 오류나 별도 승인 메시지는 남을 수 있다.

## 실기 확인

복구용 I1 또는 정상 E+LOONA를 확보한 뒤 장착 상태로 설치한다. 먼저 정상 부팅과 100% 표시를 확인하고, 실제 잉크 공급이 유지된 상태에서 인쇄를 두 번 이상 요청해 매번 확인 요구가 발생하는지 본다. 재부팅 후에도 같은지 별도로 확인한다. 시작 화면 정지나 새 오류가 있으면 복구하고 시험을 중단한다. 표시와 별개로 실제 잉크량을 관리해야 한다.
