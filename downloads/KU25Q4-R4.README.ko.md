# SC-P5380 / KU25Q4 R4 — 주 사용량의 소수 갱신 0 처리

사용자는 R3의 부팅 및 인쇄가 정상이라고 보고했다. R4는 R3 대비 실행 모듈 offset 0x2a280의 ARM 명령 4바이트만 변경한다. 원본 add r1,r0,r5를 mov r1,#0으로 바꿔 (0x22,0x23) 사용량 경로의 소수 계산 입력을 0으로 만든다. 이후 원본 나눗셈·나머지 계산과 저장 경로를 그대로 실행한다.

해당 소수 배열은 0x4495916c이며, 별도 (0x24,0x25) 경로의 0x449591ac는 유지한다. 기존 소수 잔여값도 해당 갱신 함수가 호출되면 0이 된다. 조회만으로 모든 소수 잔여값을 지우거나 모든 사용량을 고정하는 구현은 아니다. R3의 단일 사용량 쌍 조회·설정·증가 동작과 R1의 100% 잔량 표시는 보존한다. ID 0x33, 추가 누적값, LOONA, C1, 칩 없는 동작은 이번 변경 범위에 추가하지 않는다.

최종 EFU에서 코드를 다시 추출해 S1 회귀, 10개 잔량 조회, 사용량 API 경계값·비대상 쌍·호출자 스택 검사 및 실제 소수 갱신 함수를 시험한다. 소수 갱신 시험은 원본 슬롯 매핑 함수를 실행한다. 합성 역할 설정에 따른 인덱스는 실물 슬롯 배치의 입증으로 해석하지 않는다. 원본 R3에서 소수값이 증가·잔류하는 대조군과 R4에서 해당 값만 0이 되는 결과를 비교하고 다른 배열 및 인접 원소를 보존하는지 확인한다.

최종 ZIP CRC·재추출, 내부 섹션 합계·SHA-1·경계, 코드 압축 복원 일치 및 두 번째 압축 프레임 보존을 확인한다. 기존 공개키·서명 바이트를 유지하지만 수정 본문의 서명은 유효하지 않으며 선언 길이 실제+1 방식은 이전 후보와 같다. 전체 부팅·인쇄와 실물 칩 EEPROM 또는 전원 재인가 후 모든 복원 경로는 미검증이다.

R3와 동일한 카트리지·칩 조건에서 전원 켜기, 인쇄, 308223 재발 여부를 비교한다. 문제가 생기면 실기 통과한 R3를 복귀 기준으로 사용한다.
