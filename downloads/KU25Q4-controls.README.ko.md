# SC-P5300 Series / KU25Q4 A·B 대조군

기준은 사용자 제공 `FWCL14TL_KU25Q4.efu` (`08.54.KU25Q4.FY23`)입니다. 기존 SC-P5340 덤프의 KU/FY23 제품군 및 공개키와 일치합니다. 앞서 제공된 KH/FY19 `FW4838TL.efu`는 이 대조군의 입력으로 사용하지 않았습니다.

| 파일 | 변경 | 원본 동작 코드 | 실제 본문에 대한 원본 ECDSA 서명 |
|---|---|---|---|
| [A EFU](FWCL14TL_KU25Q4-A-envelope-only.efu) | 선언 본문 길이만 +1 | 본문 전체 보존 | 유효 |
| [B EFU](FWCL14TL_KU25Q4-B-original-code-reencoded.efu) | A + 첫 CROM 실행 모듈 재압축 및 섹션 검사값 갱신 | 복원 결과 원본과 동일 | 유효하지 않음 |

두 파일 모두 실제 본문 86,728,704바이트에 대해 선언 길이를 86,728,705로 설정했습니다. 원래 공개키와 서명 바이트를 보존했습니다. A는 본문이 그대로여서 실제 본문에 대한 서명이 유효합니다. B는 압축 표현과 내부 검사값이 바뀌므로 기존 서명이 새 본문에 대해 유효하지 않습니다. ECDSA 함수의 결과를 대체하지 않았습니다.

B에서 재압축한 첫 CROM은 RCX 오프셋 `0x11412e`에 있습니다. 원래 실행 모듈의 SHA-256은 `e6c02c744d84e50bebc97dc2f348525d58ddd290e011f7133fd0567a06263288`이며, 최종 EFU를 재추출·복원한 모듈과 정확히 일치합니다. 원래 Huffman 테이블의 표현 가능한 심벌만 사용했습니다. 토큰 패딩을 재계산했고 패딩 포함 DMA 출력 바이트 수는 48의 배수입니다. 후속 두 번째 프레임을 바이트 그대로 이동·보존하고 기존 할당 공간 안에 배치했습니다. 두 번째 프레임의 복원 결과도 원본과 대조했습니다.

검증: ZIP CRC·재추출 일치, 내부 2개 섹션의 메타데이터/본문 합계·SHA-1·경계, 길이 필드, 키·서명 보존, 허용 범위 밖 변경 없음, 최종 EFU에서 첫·두 번째 CROM 재복원 일치를 확인했습니다.

**실기 업데이트·플래시 기록·부팅, 전체 원본 수신 함수 실행, 하드웨어 Huffman/DMA 실행은 검증하지 않았습니다.** 이 파일들은 수신 길이 경로와 재압축·포장 경로를 분리하기 위한 대조군입니다. 잉크·유지보수 카트리지 기능이나 장착 여부 처리 코드는 변경하지 않았습니다. 소프트웨어 포장 검사 통과를 실기 업데이트 성공으로 간주하지 않습니다.
