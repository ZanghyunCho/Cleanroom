# SC-P5380 / KU25Q4 R4.6 — 소비 전 잔량 판정용 사용량 0 반환 후보

사용자 요청에 따라 R4.5 후보를 기반으로 한다. R4.5의 EPSON 제조사 조회, 비정품 표시 플래그 0 처리와 좌우 잉크 덮개 변경을 포함한다. R4.5 자체의 실기 통과 결과는 아직 제공되지 않았다. R4는 재부팅·인쇄·청소 후 값 유지를 사용자가 보고했다.

## 변경

실행 모듈 offset 0x29ba0의 12바이트만 R4.5 대비 바꿨다. (0x30,0x31) 사용량 조회 wrapper는 uint64 0을 반환한다. 해당 원본 조회를 사용하는 소비 전 검사에서 칩 상태를 반영한 사용량 대신 미사용량을 기준으로 원본 용량·요청량 비교를 실행한다. 상위 100% 표시는 기존 R4 동작을 보존한다. 저장된 원본 사용량, 칩 입출력 함수 및 칩 통신 응답 바이트 자체는 변경하지 않는다.

원본 PreInkConsumeCheck SDK wrapper 0x1659b8 → 요청 0x19 → 서버 0x1c2a0 → 0x1b0c8 → 소비 전 검사 0x190cc에서 해당 getter 호출을 확인했다. 별도의 소비 전 검사 0x2d578과 일부 잔량 계산 함수도 이 getter를 사용한다. 따라서 다른 공통 소비 전 검사 호출자에도 영향을 준다.

Initial Charge 및 CL1/CL2/CL3 각각의 전체 호출 그래프를 이 경로까지 입증하지는 않았다. 실제 칩이 모든 질의에서 100% 응답하도록 만든 물리/전송 계층 에뮬레이터가 아니다. 칩에서 직접 확인하는 모든 별도 경로까지 바뀌었다고 주장하지 않는다. 실제 작업별 검증이 필요한 후보이며 잉크 상태·장착·통신 오류를 모두 무시하는 후보가 아니다.

## 검증

최종 EFU에서 다시 추출한 코드로 5,692개 시험을 통과했다. 기존 R4.5 관련 회귀 5,532개와 소비 전 검사 비교 160개를 포함한다.

소비 전 검사는 원본과 후보의 ARM 함수를 모두 실행해 5개 내부 모드, 4개 raw 상태, 4개 요청량, 2개 사용량 조합을 비교했다. 시험한 정상 raw 상태에서 소비 사용량 때문에 부족했던 판정은 후보에서 전체 용량 기준으로 계산되었다. 전체 용량을 초과하는 요청은 원본의 비교로 여전히 부족 판정된다. 시험한 비정상 raw 상태의 결과는 대조군과 같다. 실제 용량 조회·64비트 연산·비교 결과는 시험 훅으로 대체하지 않았다. 전역 모드·상태 및 알림 전송은 시험 fixture다. 이 시험은 실제 Initial Charge/CL 단계 또는 실제 칩 통신을 실행한 것이 아니다.

ZIP CRC, 재추출, 섹션 합계·SHA-1·경계, 최종 코드 복원 일치, 두 번째 CROM 프레임과 허용 영역 밖 바이트 보존을 확인했다. 원본 공개키·서명 바이트는 유지하지만 수정 본문의 서명은 유효하지 않으며 선언 길이 실제+1 방식은 이전 후보와 같다.

## 실기 확인

기존 카트리지·칩 조건에서 부팅과 본체·PC·웹의 잔량 표시를 확인한 뒤 Initial Charge 및 CL1/CL2/CL3 결과를 각각 구분해 기록해야 한다. 부팅·인쇄만으로 네 작업을 모두 통과했다고 판단하지 않는다. 현재 이 후보의 실제 부팅·인쇄·청소·Initial Charge 결과는 미확인이다. 문제 발생 시 실기 통과한 R4를 복귀 기준으로 사용한다.
