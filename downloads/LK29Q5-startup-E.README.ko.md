# LK29Q5 진단용 E: 새 사용량의 증가 인자만 0

사용자는 D 이후 수명 종료 카트리지도 잔량 100%로 인식된다고 보고하고 E 단계로
진행을 요청했습니다. 부팅 로고 변경은 보류했습니다.

[ E EFU 다운로드 ](FW7560TL_LK29Q5-startup-E-zero-new-consumption.efu)
· [ SHA-256 ](FW7560TL_LK29Q5-startup-E-zero-new-consumption.efu.sha256)
· [ 검증 결과 ](LK29Q5-startup-E.validation.json)
· [ 검증 코드·결과 묶음 ](LK29Q5-startup-E-validation.zip)

**E는 실기 부팅과 실제 사용량 증가 중단이 아직 미검증인 후보입니다.**
D의 수명 처리와 C의 100% 수치 보고를 유지하고, 알려진 사용량 추가 함수 세 곳의
인자만 0으로 바꿉니다. 기존 누적값을 0으로 초기화하거나 실제 카운터 읽기를
0으로 속이지 않습니다. 카트리지 미장착 동작은 아직 포함하지 않습니다.

## 변경

| 주소 | 명령 변경 | 대상 |
| --- | --- | --- |
| `0x434068ac` | `mov r2,r1` → `mov r2,#0` | 1차 누적량 추가 |
| `0x434068d8` | `mov r2,r1` → `mov r2,#0` | 2차 누적량 추가 |
| `0x434068e8` | `mov r2,r1` → `mov r2,#0` | 정수 단위 및 분수 잔량 추가 |

세 함수의 원본 본문을 계속 실행하므로, 반환값과 dirty 상태 처리는 원본의
증가량 0 호출과 같습니다. D 대비 명령 위치 3곳, 실제 바이트 6개가 추가로
바뀌며 공식 원본 대비 총 6곳·11바이트가 다릅니다.

확인한 직접 호출자는 사용량 작업자 `0x43410430`의 세 호출입니다.
기존 누적값 읽기, 칩 통신·동기화, 상태·프로필·다른 오류·커버 처리는 그대로입니다.
시간 보정, 카트리지 교체 및 초기화의 정합성 처리나 직접 설정 함수는 변경하지
않았으므로 모든 상황의 모든 카운터 쓰기를 차단한다는 의미는 아닙니다.

분수 잔량이 원래의 정상 범위 0..999999인 조건에서 새 사용량을 더하지 않습니다.
범위를 벗어난 기존 데이터의 정규화는 원본의 증가량 0 처리 규칙을 따릅니다.
실제 폐잉크 발생량이 0이 되거나 물리적 수거 능력이 복구되는 것은 아닙니다.

## ARM 검증: 395건

- C/D 동작 회귀 118건: 표시, 수명 검출, 오류, 준비 상태. 참조의 사용량 추가는 0이고 준비 검사의 대상 선택은 E와 동일하게 유지합니다.
- 세 추가 함수 × 기존 값 4종 × 분수 잔량 3종 × 요청 증가량 6종: 216건. E의 0 이외 증가량 입력이 D의 증가량 0 입력과 같은 결과를 내며, 원래 누적값 읽기·반환값·dirty 표시가 보존됩니다.
- 원시 상태 8종 × 기존 값 3종 × 분수 잔량 2종의 작업자 흐름: 48건. 미장착 등 다른 오류의 준비 거부도 유지됩니다.
- D에 증가량 1을 주면 실제로 값이 증가하는 대조군 1건.
- 60번씩 호출해도 값과 분수 잔량이 누적되지 않는 반복 시험 12건.

판정 반환을 hook으로 대체하지 않았습니다. RAM/알림 전송 모델이며 실제 칩,
EEPROM 저장, RTOS 동시 실행, 전체 시작 절차나 인쇄를 실행한 결과는 아닙니다.

## 포장 검사

네 섹션의 메타데이터/본문 합계·내부 SHA-1, ZIP CRC, 압축 해제 결과의 바이트
일치를 확인했습니다. 원본 ARM 함수로 첫 섹션 117,047,296바이트의 합계 검사
성공(1)을 확인했고, 원본 로더의 기술자·DMA·LZ 재구성도 통과했습니다.
Huffman 완료 경계는 모델링한 것이며 실제 하드웨어 시험은 아닙니다.

원래 Epson 공개키·서명 바이트·최신 수신 모듈을 유지합니다. 실제 서명 대상
본문 길이 159,977,472바이트, 선언 길이 159,977,473바이트(+1)입니다.
본문 변경 때문에 일반 ECDSA 검증은 실패하며 길이 차이의 연구 경로에 의존합니다.
이번 E 전체 입력을 원본 상위 수신 함수로 다시 재생한 결과는 아닙니다.

## 실기 확인

1. 카트리지를 장착하고 E로 업데이트한 뒤 정상 부팅과 100% 표시를 확인합니다.
2. 수명 종료 카트리지의 인식이 D처럼 유지되는지 확인합니다.
3. 사용량을 읽을 수 있는 도구가 있다면 같은 카트리지의 작업 전후 누적값을 기록해 비교합니다.
   **화면의 100% 표시만으로 사용량 증가 중단을 검증할 수는 없습니다.**
4. 정지나 새로운 오류가 생기면 정상 동작이 보고된 D 또는 공식 원본으로 되돌리고 결과를 기록합니다.

D의 인식 결과는 사용자 보고이며 이 환경에서 독립적으로 확인한 실기 기록은 아닙니다.
