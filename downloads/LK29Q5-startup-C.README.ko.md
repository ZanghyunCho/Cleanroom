# LK29Q5 진단용 C: 잔량 보고만 변경

[A/B 대조군](LK29Q5-startup-controls.README.ko.md)은 모두 정상 작동했다고 사용자가 확인했습니다.
이번 조건에서는 선언 길이 +1 및 원본 코드 재압축만으로 v3의 정지가 재현되지 않았습니다.
다만 B의 실행 코드는 원본 그대로이므로, 변경된 실행 코드에 대한 부팅 무결성 처리가
원인인지까지 배제한 결과는 아닙니다.

· [ 검증 요약 ](LK29Q5-startup-C.validation.json)
· [ 검증 코드·결과 묶음 ](LK29Q5-startup-C-validation.zip)

**사용자 실기 결과: C는 정상 작동하며 낮은 잔량도 100%로 표시됩니다.**
수명 종료 카트리지는 여전히 수명 종료로 표시된다고 보고했습니다.
후속 [D: 수명 종료 검출 두 곳만 추가 변경](LK29Q5-startup-D.README.ko.md)을 준비했습니다.
검증 묶음은 생성 시점의 소프트웨어 기록이며, 이 문단은 후속 사용자 보고입니다.
유지보수 카트리지를 장착한 상태로 시험합니다. 소비량 0 처리나 미장착 동작은
아직 넣지 않았습니다. 실제 소비 카운터와 칩 통신, 초기화, 오류 처리는 원본입니다.

## 변경 범위

원본 LK29Q5 제어 모듈에서 한 명령만 변경했습니다.

```
0x43408044: ldrb r4,[r0,r5] -> mov r4,#100
```

수치 잔량을 반환하는 상태 0/6/7 경로에서 100을 반환합니다.
상태 1/2/3/4/5의 특수 반환값 105/110/114/114/119는 원본대로 남깁니다.
내부 원시 상태, 프로필 선택, 카운터 읽기·증가, 실제 잔량 계산, 상한 검사,
알림의 상태·오류 필드, 커버 상태 코드는 변경하지 않습니다.
실행 코드의 실제 바이트 차이는 3바이트이며, 원본과 다른 명령 위치는 1곳입니다.

v3의 상태·프로필·소비량 변경을 이번 후보에 함께 적용하지 않았습니다.
서명 대상 본문 길이는 159,977,472바이트, 선언 길이는 159,977,473바이트(+1)입니다.
원래 Epson 공개키와 서명 바이트 및 최신 수신 모듈을 유지합니다.
본문 변경 때문에 일반 ECDSA 검증은 실패하며, 선언 길이 차이에 관한 연구 경로에 의존합니다.

## 소프트웨어 검사

- ARM 시험 87건: 상태/저장 잔량 32건, 알림 16건, 소비량·준비 상태 흐름 3건, 오류 전이 36건.
- 원본과 대조해 내부 카운터 증가, 저장 잔량 계산, 미장착 상태 거부가 그대로임을 확인했습니다.
  합성 사용량 입력에서 내부 저장 잔량은 원본처럼 50으로 계산되지만 보고는 100이 됩니다.
- 알림의 상태·오류 필드와 이벤트는 원본대로이고 수치 잔량 필드만 변경됩니다.
- 압축 해제 결과가 시험한 모듈과 정확히 일치하고, 네 섹션의 합계·내부 SHA-1 및 ZIP CRC 검사를 통과했습니다.
- 첫 섹션 117,047,296바이트의 본문 합계를 원본 ARM 함수로 검사해 성공(1)을 확인했습니다.
- 원본 로더의 기술자·DMA 설정·LZ 재구성은 통과했습니다. 하드웨어 Huffman 완료 경계는 모델링했으므로 실제 하드웨어 해제기 시험은 아닙니다.
- 확인한 공식 17개 프레임은 모두 양수 패딩을 사용합니다. C도 이 범위를 유지하도록 정렬용 출력 없는 LZ 토큰 1개와 패딩 15개를 사용했습니다. 이 토큰은 ARM 코드에 추가되는 명령이 아니며 원본 LZ 함수로 해제 결과를 확인했습니다.

이번 C 전체 EFU를 원본 ARM 상위 수신 함수로 다시 재생한 결과는 아닙니다.
실기 전체 부팅·칩 통신·플래시·PC 업데이터·구동부 동작도 미검증입니다.
다른 파일의 수신 시험 결과를 C의 시험 결과로 대신하지 않습니다.

## 확인할 결과

C로 업데이트한 뒤 정상 대기 화면까지 시작하는지, 모터·펌프가 반응하는지,
유지보수 잔량 표시가 100%인지 확인합니다. 정상 동작하면 다음 기능을 한 그룹씩
추가 검토할 근거가 됩니다. 정지하면 공식 원본 또는 정상 동작한 대조군으로 되돌리고,
단일 잔량 보고 변경 및 변경된 실행 코드의 부팅 처리부터 조사합니다.

A/B 정상 동작은 사용자 보고이며, 이 환경에서 직접 프린터를 관찰하거나
설치된 플래시 내용을 읽어 독립적으로 확인한 것은 아닙니다.
