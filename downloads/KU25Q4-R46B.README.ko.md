# SC-P5380 / KU25Q4 R4.6B — 소비 전 검사 내부 값만 변경

사용자는 R4.6A에서 오류 308223이 재발했다고 보고했다. R4.6A는 R4에서 전역 사용량 getter의 12바이트만 바꾼 후보였으므로 그 변경이 실패를 유발한다는 실기 근거가 있다. 구체적인 내부 오류 원인, 예외 PC 및 스택은 확인하지 않았다.

R4.6B는 실기 통과한 R4를 다시 기준으로 한다. R4.6A나 R4.5를 기반으로 하지 않는다. 전역 사용량 getter 0x29ba0 및 그 다른 호출자 코드는 R4와 동일하다.

## 이번 변경

소비 전 검사 함수 0x190cc 안의 offset 0x19234~0x1923b, ARM 명령 두 개(8바이트)만 변경했다. 해당 지점의 사용량 getter 호출 대신 r0/r1에 64비트 0을 넣는다. 이후 요청 소비량과 용량의 원본 비교 연산은 유지한다. 이렇게 이 호출 지점에서 사용하는 사용량 값만 0이 되고 다른 사용량 조회는 R4의 실제 값을 반환한다. 저장된 사용량과 칩 통신은 변경하지 않는다.

R4.5의 제조사·정품 표시·좌우 덮개 변경은 포함하지 않는다. 앞서 제외한 전역 getter를 다시 0으로 만들지 않는다.

## 검증 범위와 한계

최종 EFU에서 실행 코드를 다시 추출해 R4 대비 위 8바이트만 다른지 확인한다. 기존 R4 회귀 및 소수 갱신, 소비 전 검사 비교 160개, 전역 사용량 getter의 60개 경계값·RAM 보존 시험을 실행한다. 전역 getter가 0이 아닌 저장값도 그대로 반환하는지 확인한다. 소비 전 검사에서는 정상 상태의 용량 비교 변화와 비정상 raw 상태의 결과 보존을 비교한다. 이 상태·모드·알림 전송은 fixture이며 용량 연산·판정 함수 결과를 훅으로 대체하지 않는다.

이 후보는 실제 부팅 또는 Initial Charge/CL1/CL2/CL3 통과를 입증하지 않는다. 모든 해당 작업의 전체 호출 그래프를 입증한 것도 아니다. 오류가 해결됐다는 판정은 실기 결과가 있어야 가능하다. NVRAM에 저장된 실제 상태의 원상복구 여부도 이 파일의 바이트 검증으로 보장하지 않는다.

ZIP CRC, 재추출, 내부 섹션 합계·SHA-1·경계, 최종 코드 압축 복원 일치, 두 번째 CROM 프레임 및 허용 영역 밖 바이트 보존을 확인한다. 원래 공개키·서명 바이트는 유지하지만 수정 본문의 서명은 유효하지 않으며 선언 길이 실제+1 방식은 기존 후보와 같다.

## 실기 비교

R4가 통과한 동일 카트리지·칩 조건에서 먼저 전원 켜기와 인쇄 및 308223 재발 여부를 확인한다. 정상이라면 청소 결과를 단계별로 기록한다. 문제가 생기면 R4를 복귀 기준으로 사용한다. R4.6A와 R4.6B 파일을 구분한다.
