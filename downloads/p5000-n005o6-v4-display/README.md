# SC-P5000 N005O6 V4 — LLK/V 표시 자동 전환 실험본

[EFU 다운로드](https://github.com/ZanghyunCho/Cleanroom/raw/refs/heads/delivery/p5000-n005o6-v4-display/downloads/p5000-n005o6-v4-display/SC-P5000_N005O6_VIRTUAL-INK-RTC_V4_VMODE-DISPLAY_UNVERIFIED.EFU)

REV3를 기준으로 슬롯1의 표시 코드를 현재 CSIC 잉크 구성에 따라 갱신한다.

| 저장 구성 | 네이티브 CSIC 구성 | 슬롯1 표시 | 내부 제품ID | 잉크 종류 |
|---|---:|---|---:|---:|
| LLK (NVRAM2) | 1 | T9139 | 9139 | 149 |
| V (NVRAM1) | 2 | T913D | 9130 | 152 |

V4는 구성을 강제로 V로 바꾸지 않는다. 현재 프린터 구성에 맞춰 표시를 바꾼다.
V 구성용 NVRAM 수정본은 [별도 다운로드](https://github.com/ZanghyunCho/Cleanroom/tree/delivery/p5000-nvram-v-mode/downloads/p5000-nvram-v-mode)다.
새 EFU에는 장비 개인 NVRAM 백업을 포함하지 않았다.

가상 레코드가 이미 생성되어도 조회 때 표시를 갱신하며 LLK로 돌아가면 T9139로 복원한다.
다른10개 잉크의 코드·모델 선택, REV3의 부팅 후 최초 생성 시 RTC 연월 반영,
REV2의 커버 입력 처리와 기존 가상 장착·100% 잔량 정책을 유지한다.
**소비량 누적·5% 미만 커버 리필 정책은 포함하지 않았다.** 유지보수 프로필과
NVRAM 할당·RTOS 잠금도 이번에 변경하지 않았다.
표시 코드는 가상 표시용이며 Epson이 발급한 고유 시리얼이 아니다.

## 파일 검증

- EFU 크기: 9,849,257바이트, 제공된 원본과 동일.
- SHA256: `d82a8790c604b37399a58265fb327a91de6da5c9588c973874b2c4cd8171cb6c`
- 원래 압축 스트림 전체 길이와 ZIP 엔트리 배치·저장 DEFLATE 블록을 보존했다.
- 전체 디코딩 결과와 선언한 코드 변경, 알려진 가산 체크섬·ZIP CRC를 대조했다.
- 전체 회귀 시험60개 통과. 이 중 신규 표시·포장 검사는10개다.
- 네이티브 명령 모형에서 LLK/V 양쪽11개 슬롯, 기존 레코드의 모드 왕복,
  스택·반환주소 보존, RTC·소비량 고정 정책을 시험했다.
- 외부 RTC 호출 등은 모형에서 대체했다. 장비의 업데이트 수락·부팅·인쇄는 미검증이다.
- 기존 가상화가 우회한 ReadDev 본체 안의 여유를 재사용했다.
  모든 간접 진입 부재를 증명한 것은 아니다. 상세 주소는 policy.json에 있다.

## 확인 및 NVRAM 비교 순서

1. V4를 적용하고 부팅한 뒤 현재 LLK/V 구성과 슬롯1의 색상·표시 코드를 확인한다.
2. 비교할 구성을 확정하고 기기가 대기 상태가 된 다음 첫 NVRAM을 백업한다: `before_V4.bin`.
3. 같은 부팅 세션에서 정상 인쇄1장을 수행한다.
4. 재부팅·커버 열기/닫기·설정 복원·수동 청소 없이 두 번째 NVRAM을 백업한다: `after_V4.bin`.
5. 두 파일과 인쇄한 작업 종류를 함께 제공한다. 자동 청소가 있었다면 그 사실도 기록한다.

현재 잔량 표시는 기존처럼100%로 유지된다. 이 두 백업은 실제 사용량이 어느
본체 카운터·누적 기록에 반영되는지 비교하기 위한 자료다.
이전 정상 동작 REV3와 원본 NVRAM 백업은 보관한다.
