## 변경한 동작

펌웨어의 설정된 유지보수 슬롯 수는 원본 그대로 **2개**입니다. 정상 숫자 잔량 상태에서 두 슬롯의 보고 잔량과 잔량 계산을 100으로 고정했습니다. 미장착·통신 오류 등을 표시하는 기존 상태별 오류 인코딩은 보존했습니다. 오류를 숫자 100으로 덮어쓰지 않습니다.

유지보수 사용량 ID `0x1d`, `0x1e`, `0x26`에 한해서 공통 읽기·설정·증가 함수를 처리합니다. 읽기 때 해당 슬롯의 누적값을 원래 setter를 통해 실제 RAM에 0으로 기록하고 0을 반환합니다. 설정·증가 요청도 0을 기록하도록 했습니다. 따라서 기존 값이 남아 있는 상태에서 증가분만 0으로 만드는 방식과 다릅니다. 원래 setter의 값 비교와 dirty 표시를 사용하며, 이미 0이면 새 dirty 변경을 만들지 않습니다. 정수 미만의 누적 나머지도 유지보수 사용량 읽기와 소수 단위 사용량 갱신 때 해당 슬롯만 0으로 지웁니다.

다른 ID는 원본 함수 본문을 실행합니다. 슬롯을 구분하는 주소 계산과 다른 슬롯의 값은 보존합니다. 잉크 카운터·프린터 모드·커버·기계 동작·칩 통신 코드는 변경하지 않았습니다. 카트리지 없이 운전하는 기능이나 모든 수명/오류 상태 해제 기능은 포함하지 않습니다.

## 원본 ARM 실행 검증

최종 EFU에서 RCX와 첫 CROM을 다시 추출·복원한 코드로 **1,923개 시나리오**를 통과했습니다. 원본과 수정본의 실제 ARM 명령을 Unicorn에서 실행했고 함수 판정값을 바꾸는 훅은 사용하지 않았습니다.

| 검사 | 시나리오 |
|---|---:|
| 설정된 슬롯 수 2 확인 | 1 |
| 두 슬롯의 유지보수 읽기·설정·증가와 기존 누적값 제거 | 432 |
| 다른 사용량 ID의 반환·RAM·dirty 표시 원본 대조 | 972 |
| 유지보수 전용 helper·정수/소수 단위 처리 | 360 |
| 읽기 시 소수 누적값 제거와 반대 슬롯 보존 | 24 |
| 상태별 잔량 보고·오류 인코딩 보존 | 100 |
| 잔량 계산 | 8 |
| 원본의 양수 소비가 실제 증가하는 대조 | 1 |
| 반복 혼합 요청과 슬롯 분리 | 1 |
| 실제 두 슬롯 소비 worker의 원본/수정본 대조 | 24 |

두 슬롯 소비 worker `0x4461e120`을 원본 프로필 0 데이터와 RAM 입력으로 실행했습니다. 원본은 양수 소비에서 값이 증가했고, 수정본은 두 슬롯의 3종 사용량과 소수 누적값이 0이 됐습니다. 다른 슬롯/미사용 인덱스의 값도 보존됐습니다. 프로필 선택자는 초기화되지 않은 값 `0xff` 대신 RAM fixture에서 0으로 초기화했고 원본 프로필 데이터 자체는 수정하지 않았습니다.

## EFU 포장 검증

원래 공개키와 서명 바이트를 보존하고 선언 본문 길이는 A/B와 같은 실제 길이 +1로 설정했습니다. 수정된 본문의 원래 ECDSA 서명은 **유효하지 않습니다**. ECDSA 판정 코드를 성공으로 대체하지 않았습니다.

최종 파일의 ZIP CRC·재추출 일치, 2개 섹션의 메타데이터/본문 합계·SHA-1·경계, 허용 범위 밖 바이트 보존을 확인했습니다. 첫 CROM 재복원 결과가 시험 코드와 일치하며 후속 두 번째 프레임도 바이트·복원 결과를 보존했습니다. 원래 Huffman 테이블 심벌만 사용했고 패딩 포함 DMA 출력 크기는 48바이트의 배수입니다. 두 프레임은 원래 할당 범위 안에 들어갑니다.

EFU SHA-256: `7956e54ab76c5be66bb66a8b67ef5d6fdab697fb262b2f6f98603e5e08f7a890`

최종 복원 실행 모듈 SHA-256: `49bd6d6d5eedaa7c869405bddd4f34e30089ee224c1763cac9eb756df21951f5`

## 실기 검증 범위와 기록

**실기 업데이트·전체 부팅·인쇄·실제 폐액 발생 전후 비교는 아직 수행하지 않았습니다.** 실제 카트리지 EEPROM의 기록 내용과 재부팅 후 복원 동작, 전체 수신 함수, 하드웨어 Huffman/DMA 실행도 검증하지 않았습니다. 검증한 것은 원본 ARM 회계 함수의 RAM 값·dirty 표시와 최종 EFU 포장입니다. 코드가 모든 직접 RAM/DMA 기록을 가로채는 것은 아니며 원본 경로 밖의 기록까지 없다고 주장하지 않습니다.

공식 KU25Q4와 A/B의 업데이트·부팅 결과를 기준으로 S1을 비교합니다. 정상 장착 상태에서 두 카트리지 각각의 잔량을 기록하고, 실제 폐액이 발생하는 동작 전후 및 재부팅 전후에 두 잔량과 사용량을 비교해야 실기 고정을 확인할 수 있습니다. 아직 그 결과가 없으므로 완성된 실기 성공본으로 표기하지 않습니다.
