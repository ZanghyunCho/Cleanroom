## 대상 구분 근거

원본 코드의 커버 레코드 `0x4487c668`에는 6개 종류가 구분돼 있습니다. 잉크 덮개는 `ms_Cover_CartridgeCoverOpen/Close`와 `..._Full` 콜백을 가진 **type 2와 3**이며, 각각의 인터록 분류 필드는 **0**입니다. 원본 `ms_Cover_IsInterlockCoverOpen` 함수는 해당 필드가 **1**인 항목만 검사합니다. type 0의 필드는 1이며, 그 항목의 상태와 인터록 판정은 그대로 보존했습니다. 이는 잉크 덮개를 일반 보호 커버와 구분한 코드상의 근거입니다. 실제 하드웨어를 분해·측정해 확인한 결과는 아닙니다.

| 대상 | 상태/센서 ID | 원본 인터록 분류 |
|---|---|---:|
| 잉크 덮개 home 쪽 (type 2) | 0x6009 / 0x602f | 0 |
| 잉크 덮개 full 쪽 (type 3) | 0x600a / 0x6030 | 0 |
| 별도 인터록 대상 (type 0) | 0x6000 / 0x6027 | 1 — 유지 |

## 변경

두 잉크 덮개의 캐시 조회는 닫힘(0)을 반환하고 상태 저장도 각 슬롯에 0을 기록합니다. 두 잉크 덮개만 모으는 집계 함수는 닫힘/준비(1)를 반환합니다. DSM의 32비트 상태 조회에서 위 네 잉크 ID만 0으로 처리하고 다른 ID는 원본 본문으로 전달합니다.

잉크 덮개 열림 콜백 type 2와 type 3은 각각 기존의 해당 닫힘 콜백으로 연결했습니다. 따라서 식별한 소프트웨어 경로에서 열림 대기 대신 닫힘 상태 전달/해제 흐름이 실행됩니다. 잉크 교체를 위한 덮개 열림 안내도 동일 경로에서는 닫힘으로 처리될 수 있습니다.

별도 인터록 분류 테이블·판정 함수와 비상정지 핸들러, 다른 커버 함수는 바이트 그대로 보존했습니다. 원래 카트리지 장착 여부·칩 통신 오류, 잉크/폐액 회계 처리, 모터/헤드 제어는 이 변경의 대상이 아닙니다.
