# SC-P10000 V4.5 — ILS 원본 복원 진단 후보

**V4.5는 배포 식별 이름이며, 펌프 문제 해결판으로 검증된 것은 아닙니다.** V2는 정상이고 V3 이후 인쇄·헤드 청소·자동 노즐 검사가 안 되며, 현재 V4에서 ‘용지를 감지하지 못했습니다’ 오류와 펌프 미동작이 보고됐습니다. 기존 일반 동작/표시 성공 보고를 실제 인쇄 동작 성공으로 해석하면 안 됩니다.

이번 진단 후보는 **현재 설치 버전인 공개 V4를 기준으로**, 모듈 오프셋 `0x3f3a4`의 ILS 조회 첫 8바이트만 원본으로 복원합니다. 나머지 압축 해제 모듈은 V4와 동일합니다. 원시 디바운스 값이 그대로 조회 결과로 나오는 15개 시험을 통과했습니다. 펌프·용지 감지 인터록을 강제로 허용하거나 펌프를 강제 구동하는 코드는 넣지 않았습니다.

V3/V4에는 별도 메타데이터 결함도 확인됐습니다. 순중량 필드 680과 정격 용량 필드를 혼동했으며, 원본 클래스 2 파서는 각각 680과 700을 기록합니다. 원본 30개 경우 및 별도 수정 코드 회귀 시험으로 확인했습니다. **변수를 섞지 않기 위해 이 700 수정은 이번 ILS 진단 EFU에 포함하지 않았습니다.**

## 목적과 확인

정상 기준은 기존 V2입니다. 프린터를 정상 사용해야 한다면 먼저 V2로 돌아가세요. 이 진단 파일은 동일한 용지·카트리지 상태·실제 잉크 공급 조건에서 V4와 비교해 ILS 상수화의 관여 여부를 분리하기 위한 후보입니다.

- 이 후보에서 증상이 해소되면 ILS 조회 변경의 관여를 조사할 근거가 됩니다. 모든 V3 변경이 올바르다는 뜻은 아닙니다.
- 증상이 계속되면 ILS 변경 단독으로 설명할 수 없습니다. 다른 V3 가상화 변경과 상위 작업 허용 조건을 이어서 조사해야 합니다.
- 펌프 미동작은 용지 감지 오류로 작업이 먼저 중단된 결과일 수도 있습니다. 현재 원인/결과 관계는 미확정입니다.

실제 잉크 공급과 폐잉크 수거 경로를 유지하세요. 공급이 없는 상태에서 인쇄·청소를 반복하거나 강제 펌프 구동을 하지 마세요. 정확한 오류 문구/코드, 발생 단계, 펌프 반응을 기록하면 다음 원인 분리에 사용할 수 있습니다.

## 검증 및 한계

공개 V4의 모듈 SHA-256 재현을 확인한 뒤 정확히 8바이트만 복원했습니다. 원본 ARM ILS 조회 입력/출력, 원본 압축 해제기의 전체 모듈 복원, 기존 유지보수 사용량/여유량 70개 호출, 다섯 외부 블록 합계, ZIP CRC/각 내부 파일 해시를 확인했습니다. 실제 펌프 구동·용지 감지·인쇄는 검증하지 못했습니다. OS와 하드웨어의 전체 동작을 검증한 결과가 아닙니다.

파일: `P10000_FM001PA_V4.5.EFU`

SHA-256: `2ec218b593e7a6cfb43accc71377c22b8acd2892ae5790064a4d1a5af98f7497`

재현: `python firmware/P10000/build_efu_research.py --ils-diagnostic`

V4.5는 사용자가 업로드를 승인한 기존 진단 EFU와 바이트 내용 및 SHA-256이 동일합니다. 이름만 변경했으며, 장치 내부 펌웨어 버전 문자열은 FM001PA로 유지합니다. 정품/잔량 100% 및 유지보수 가상화는 V4와 동일하게 유지합니다.
