# SC-P5000 N005O6 가상 잉크 코드·RTC 제조 연월 — REV3 실험본

**SC-P5000 전용이다. REV3의 장비 수락·부팅·인쇄·RTC 값은 아직 실기 미검증이다.**
사용자가 동작을 확인한 REV2의 커버 입력 마스크는 그대로 포함한다.
실패한 REV1의 상위 콜백 변경은 사용하지 않는다.

## 잉크 11개

기존 N005O6의 가상 칩 읽기/쓰기 및 장착 설정을 유지한다.
소비량을 0으로 재설정하고 11개 장착 플래그를 1로 설정하는 원본 가상 경로를 모델에서 확인했다.
실물 잉크가 공급되는지 측정하는 기능은 아니다. 실제 잉크 공급은 별도로 필요하다.

| CRTEST000A | G 녹색 | T913B | 9162 |

기존 10문자 표시 필드에는 모델 코드와 공백 5개를 넣는다. Epson 발급 고유 시리얼을 생성하는 기능은 아니다.
내부 제품 ID도 현재 잉크 모드의 T913 대응 표를 선택한다. 용량 프로필 200은 변경하지 않는다.
이 표는 사용자 화면의 LLK 구성 기준이다. 다른 대체 잉크 모드의 실기 동작은 미검증이다.

## 제조 연월

매 부팅 후 가상 레코드가 처음 생성될 때 원래 RTC 달력 갱신 함수 0x10027B70을 호출하고
그 결과 버퍼 0x103F6010의 연·월을 가상 제조일 필드로 넣는다.
각 레코드는 같은 부팅 중에는 제조일을 유지한다. 영구 저장 영역은 추가하지 않는다.

제조일 워드 +0x42의 연도 6비트/월 4비트만 바꾸며 하위 6비트는 보존한다.
지원 범위는 2000~2063년, 1~12월이다. 범위 밖/잘못된 날짜에서는 기존 템플릿 2000/01을 유지한다.
프린터 RTC가 정확한지는 장비에서 확인해야 한다. 호스트 날짜를 대신 넣지 않았다.
RTC API의 실제 부팅 준비 시점·잠금·오류 동작 전체는 실기 검증하지 않았다.

## 코드 공간·검증 한계

기존 가상 ReadDev 진입점이 이미 다른 가상 함수로 분기하는 영역의 원래 본문 일부를
새 헬퍼 158바이트에 재사용했다. 새 RAM이나 저장 영역을 배정하지 않는다. 일반 스택 32바이트를 사용한다.
직접 분기 조사 및 원래 진입점 확인은 했지만, 모든 간접 제어 흐름 부재를 완전히 증명한 것은 아니다.
헬퍼는 원래 leaf 조회 함수의 복귀 주소를 보존하고 점프로 원래 처리에 복귀한다.

새 모델/날짜/스택·복귀/RTC 오류 범위/REV2 유지 시험 7개와 포장 시험 4개를 통과했다.
기존 가상 칩/커버 시험 포함 회귀 시험 전체 36개 통과.
실행 모델은 RTC 반환 달력, 외부 호출 및 호출 규약을 모형화한다. 실제 RTC/RTOS/인쇄 전체 검증이 아니다.

LZSS 국소 재인코딩에서 길이 증가/감소를 상쇄했다. 일부 중간 압축 바이트 위치는 이동하지만
압축 블록 전체 길이·후속 블록 위치는 원본과 같다. 전체 복원 결과와 코드 후보가 정확히 일치한다.
ZIP 원본의 151개 uncompressed DEFLATE 블록을 보존하고 RCX 데이터와 해당 CRC만 갱신했다.
모든 ZIP 항목의 위치/길이/리소스를 확인했다. 기타 펌웨어 구성요소는 원본과 같다.

## 유지보수 카트리지

사용자 화면의 T6191/PX17MB1, T6190/PXBMB1은 별도 프로필이다.
이번 REV3에서는 이 두 유지보수 카트리지의 장착/사용량/날짜를 변경하지 않았다.
잉크 11개의 가상화 결과를 유지보수 두 개에 적용했다고 해석하면 안 된다.

## 시험 순서

1. 공식 원본 복구 도구와 동작 확인된 REV2 파일을 보관하고 파일 해시/모델을 확인한다.
2. 업데이트 후 부팅과 11개 모델 코드, 제조 연월을 확인한다.
3. 프린터 RTC 설정과 표시 연월이 같은지 비교한다. 전원을 정상 종료 후 다시 켜서 재확인한다.
4. 이상이 없을 때만 작은 인쇄물/노즐 체크 및 커버 동작을 확인한다.
5. 부팅 실패/멈춤/인식 오류가 있으면 반복 명령을 중단하고 공식 복구 절차를 따른다.

커버 안에 손을 넣은 상태에서 인쇄하지 않는다. 다른 모델에는 사용하지 않는다.
