## 이미지와 저장 형식

KU25Q4의 RCX `0x41412e` CROM 자원에서 480×272 EPSON 화면을 복원해 사용자 제시 화면과 시각적으로 대조했습니다. 이 자원은 **R,G,B,A 순서**이며 알파는 255입니다. 다른 모델에서 사용한 A,R,G,B 순서를 적용하지 않았습니다.

검은 배경 LOONA 소스는 저장소 `LK29Q5-LOONA-validation.zip`에 보존된 원본 PNG를 사용했습니다. 이번 메시지의 LOONA 이미지와 화면상 일치함을 확인했습니다. 현재 인라인 첨부의 파일 바이트는 실행 환경에 노출되지 않아 첨부 파일 자체와의 해시 일치까지 확인한 것은 아닙니다. 소스 PNG를 다시 그리거나 리사이즈하거나 색을 바꾸지 않았습니다. 해당 보존 원본과 최종 EFU에서 복원한 픽셀은 정확히 일치합니다.

소스 PNG SHA-256: `c4192fb7f7173da0192dfa9b9c91bee36b1d721fddddbabc2d522f8c221cfe2a`

## 보존·포장 검증

로고의 픽셀 522,240바이트를 교체하고, 같은 복원 자원의 뒤에 붙은 코드·데이터 **644바이트**는 그대로 보존했습니다. 압축 프레임은 9,005바이트로, 원래 프레임 뒤가 전부 FF인 16KiB 범위 안에 배치했습니다. 압축 테이블은 원래 Huffman 테이블을 유지하고 패딩과 DMA 출력 정렬을 검사했습니다.

S2와 비교한 변경 범위는 로고 자원 슬롯, 첫 섹션 본문 합계, 해당 섹션 SHA-1뿐입니다. 그 외 바이트는 S2와 같습니다. S2 실행 모듈도 압축 해제 후 바이트 단위로 일치합니다. S2에서 통과한 ARM 7,063개 시험의 실행 코드를 그대로 유지한 것이며, 이 이미지 교체만을 위해 그 시험을 다시 실행했다고 주장하지 않습니다.

ZIP CRC·재추출 일치, 내부 2개 섹션 합계·SHA-1·경계, 최종 CROM의 이미지 픽셀·뒤쪽 코드 일치를 확인했습니다. 원래 공개키·서명 바이트와 S2의 선언 본문 길이 실제+1을 보존했습니다. 수정된 본문에 대한 원래 ECDSA 서명은 유효하지 않으며 암호 함수 판정 코드는 바꾸지 않았습니다.

EFU SHA-256: `633456ec029012746a6c814161911c6a19532a3034d99a90e2d0cd1ee82273ef`

S2와 동일한 실행 모듈 SHA-256: `2c23dd32742e4060cdeb1c9e20a9da49d6d54072094d1e4eb0082826f7661453`

## 실기 범위

**이 로고 결합본의 실제 업데이트·전체 부팅·패널 표시는 미검증입니다.** 위 이미지는 최종 EFU의 소프트웨어 복원 결과입니다. 패널 제어기·하드웨어 Huffman/DMA를 실행한 결과가 아닙니다. 사용자의 S1 통과 보고를 이 결합본의 성공 결과로 간주하지 않습니다. 전원 투입 시 LOONA 표시 여부와 이후 정상 기동, 기존 S2 잔량·사용량 처리를 실기에서 별도로 확인해야 합니다.
