# P7500 가상 카트리지 런타임

가상 시리얼 세대, 잉크 소비량, 커버 개폐 초기화, 저장·복원을 구현한 C 코드와
원본 ARM 함수 연결 시험이다. **현재 기록용 IC13/IC14 펌웨어가 아니다.**

## 구현된 동작

- 12슬롯 700ml 명칭: GY/T44M7, VM/T44M3, OR/T44MA, PK/T44M1,
  VLM/T44M6, LGY/T44M9, LC/T44M5, Y/T44M4, GR/T44MB, MK/T44M8,
  V/T44MD, C/T44M2. 명칭은 사용자가 지정한 프로필이다.
- 소비량은 40비트 상한까지 증가한다. 표시 잔량 계산은 확인한 원본 ARM 수식과
  맞춘다. 용량은 호출자가 원본 프로그램의 소비량 단위로 공급해야 한다.
  `nominal_ml=700`과 내부 카운터 용량은 서로 다른 필드다.
- 커버를 열었다 닫으면 해당 커버의 **표시 잔량 10% 미만 슬롯만** 초기화한다.
  정확히 10%, 중복 닫기, 열기 없는 닫기는 초기화하지 않는다.
- 대상 슬롯의 소비량 0과 32비트 세대 증가를 한 저장 트랜잭션에 넣는다.
  여러 대상 슬롯도 한 트랜잭션으로 처리한다.
- 잉크 시리얼은 `V` + 슬롯 1자리 HEX + 세대 8자리 HEX의 10문자다.
  예: 슬롯 0의 세대 0은 `V000000000`, 세대 1은 `V000000001`.
  Epson이 발급한 시리얼이 아니다. 유지보수 논리 프로필은 `MC00000000`이다.
- 유지보수 논리 프로필은 장착/사용 가능 100%를 공급한다. 실제 폐잉크 용량을
  측정하지 않는다. 제조사 정보는 `EPSON`, 가상화 여부는 별도 필드로 제공한다.
- 기존 네이티브 코드가 과거의 더 작은 소비량이나 0을 보고해도 누적 소비량을
  줄이지 않는다. 소비량 감소는 세대 증가와 함께 수행하는 커버 초기화로 제한한다.
  따라서 원본의 하향 카운터 보정 동작까지 그대로 재현하는 구현은 아니다.

## 저장 형식과 실패 처리

`vr_io`는 서로 독립된 두 저장 뱅크를 요구한다. 각 뱅크의 논리 기록은 512바이트다.
raw NOR 직접 백엔드를 만든다면 두 뱅크를 같은 소거 블록에 두어서는 안 된다.
새 네이티브 NV 백엔드는 이 512바이트 형식을 두 개의 128바이트 논리 기록으로
변환하고 기존 저장 서비스에 기록을 맡긴다. 새 raw 저장 주소를 배정하지 않는다.
자세한 연결과 실기 검증 한계는 [네이티브 NV 백엔드](native_nv.ko.md)를 참조한다.

기록은 명시적 little-endian 형식이며 버전, 64비트 순번, CRC-32, 세대·소비량·용량을
포함한다. 비활성 뱅크를 소거하고 본문을 쓴 후 동기화·재독출한다. 커밋 표식은
마지막에 기록하고 다시 동기화·재독출한다. 이 순서를 마친 뒤에만 RAM 상태를
새 상태로 바꾼다. 커밋 결과가 불명확한 오류는 장애를 고정하고 재초기화로
저장 결과를 확인하기 전까지 다음 갱신을 허용하지 않는다.

비어 있는 저장소만 명시적으로 초기화할 수 있다. 양쪽이 손상됐거나 알 수 없는
버전이면 사용량을 0으로 만드는 공장 초기화를 하지 않는다. 한 기록이 손상되면
유효한 이전 기록으로 복원한다. **이전 기록 복원은 마지막 트랜잭션을 되돌릴 수
있다.** 임의의 저장 매체 손상에도 시리얼이 절대 재사용되지 않는다는 보장은 없다.
열림 표식은 재부팅 시 버리므로, 재시작 직후의 닫기만으로 초기화되지 않는다.

호출은 상위 디스패처에서 직렬화해야 한다. 재진입 방지 플래그는 OS 뮤텍스를
대신하지 않는다. 현재는 소비량 배치마다 저장 트랜잭션을 실행하므로 실제 NOR
백엔드 연결 시 쓰기 빈도와 마모 분산 계약을 확인해야 한다.

## 원본 ARM 연결

`native_adapter.c`는 소비량 Get/Set/Add, 커버 상태 설정, 잉크 식별자 읽기,
장착 여부 포인터, 잔량 조회, 유지보수 상태·잔량·오류 조회에 연결한다.
상위 잉크 칩 검사와 상태 검사 작업도 물리 드라이버 호출 없이 완료한다.
소비량의 `0x2F/0x30` 식별자 조합만 새 저장소로 연결하고 다른 조합은 원래 함수로
넘긴다. 원본 함수 포인터는 덮어쓴 진입부 자체가 아니라 검증된 트램펄린이어야 한다.
저장 오류는 기존 void 호출에서 사라지지 않도록 오류 콜백과 장애 상태로 전달한다.

`probe_compiled_bindings.py`는 에뮬레이터 RAM의 원본 함수 16곳을 실제 8바이트 ARM
분기로 바꾼다. 카운터·커버·식별자·장착 상태 변환은 컴파일한 C/ARM 코드가 실행한다.
Python 훅은 저장 매체 입출력, OS 알림, 오류 수집만 제공한다. 트램펄린이 필요한
원본 진입부는 PC 상대 명령이 없는지 확인한다. 원본 함수로 돌아가지 않는 완전
대체 getter에는 잘못된 트램펄린을 만들지 않는다.

잉크 RAM 미러에서는 확인한 시리얼 10바이트와 제조사 5바이트만 갱신한다.
제품·인증·알 수 없는 비트는 보존한다. 유지보수 8바이트 정보 구조는 원본
UpdateWasteStatus의 정상 상태 배치와 비교해 공급한다.

**이는 Epson 칩의 ASIC/SPI 프레임과 인증 절차 전체를 에뮬레이션한 결과가 아니다.**
상위 네이티브 정보 경로의 가상화이며, 실물에서 정품 카트리지로 판정되는지는
검증하지 않았다. 원본 하위 칩 작업자가 계속 실행될 때의 상태·IRQ·타임아웃 경로도
추가 확인이 필요하다. 업데이트 서명 검증 경로는 수정하지 않았다.

## 재현

저장소/작업 폴더 최상위에서 다음을 실행한다. 기존 격리 체크아웃을 사용하며,
사용자가 요청하지 않은 Git worktree를 만들지 않는다.

```sh
python3 -m pip install --target tools capstone==5.0.9 unicorn==2.1.4 pyelftools==0.33 ziglang==0.13.0
python3 prepare_original.py /첨부파일/IC4.zip
python3 crom.py original/merged.bin decoded
python3 runtime/verify.py
```

호스트 빌드는 GCC, ARM 빌드는 Zig 0.13을 사용한다. ARMv5TE 정수 명령으로 빌드해
Cortex-A9에서 VFP/NEON 활성화나 작업 문맥 저장 방식을 가정하지 않는다.
`-rdynamic`은 격리 시험에서 호출할 모든 진입점을 보존하기 위해 필요하다.
Zig 캐시는 읽기 전용 HOME 대신 `build/` 아래에 둔다.

결과는 `analysis/runtime-verification.json`에 이번 실행의 소스·ELF 해시와 함께
모은다. 호스트 시험은 바이트별 저장 중단 1,025곳, 비트 손상 4,096건,
커버/잔량 경계 60건, 별도 프로세스의 fsync 파일 복원 등을 포함한다.
ARM 시험은 원본 함수의 실제 분기 연결, 12슬롯 시리얼 변경과 장착 상태,
13개 프로필 재시작 복원, 유지보수 정보 구조, 저장 오류 전달을 확인한다.

`arm.ld`의 0x45000000, 시험의 0x46000000/0x47000000은 **격리 시험 주소**다.
프린터의 코드·RAM·저장 영역으로 배정한 주소가 아니다. 실제 RAM 충돌 없는 배치,
초기화 시점, 저장 뱅크와 소거·동기화 계약을 확인하기 전에는 IC13/IC14 BIN에
이 주소를 넣어서는 안 된다. 실물 부팅·인쇄·센서·전원 차단·EFU 수용은 미검증이다.

원본 덤프, 개인키, 도구 캐시, 에뮬레이터 출력물을 소스 배포에 포함하지 않는다.

## 물리 통신 분리 경계 조사

`probe_dispatch_boundary.py`는 원본 ARM 디스패처와 설정 함수를 실행한다.
현재 원본 설정에서 슬롯 0~5는 access 0, 슬롯 6~11은 access 1로 연결되고,
잉크는 driver 1, 유지보수 access 2는 driver 0을 선택한다. 콜백 테이블은
0x4365C444에 있으며 행 크기는 116바이트다. 이는 원본 코드 내 위치이며
새로운 프린터 RAM 배치 주소가 아니다.

12개 양성 대조 호출은 실제 물리 드라이버 진입점을 확인한 뒤 시험 훅으로
즉시 반환한다. 드라이버 본문은 실행하지 않는다. 에뮬레이터에서 두 행의
콜백을 비운 뒤에는 30개 호출에서 해당 드라이버 진입이 발생하지 않는다.
그러나 원본 폴링과 결과 수집을 실행해도 세 요청의 pending 상태와 결과
버퍼가 그대로 남는다. 따라서 **콜백 삭제만으로 가상 카트리지 통신이
완성되지 않는다.** 작업 완료 상태와 결과 구조를 공급하는 상위 어댑터가
필요하다. 모든 하드웨어 진입 경로가 차단됐다는 증명은 아니다.

물리 ASIC/SPI 프로토콜 재현은 이 상위 대체 방식의 필수 조건이 아니다.
영구 저장도 기존 DSM 논리 항목 API를 활용할 수 있으므로 새 raw NVRAM 주소
할당이 반드시 필요한 것은 아니다. DSM 비동기 SetBuffer를 직접 연결하는 대신,
현재는 완료 응답을 기다리는 별도 네이티브 NV API에 백엔드를 연결했다.
확인한 DSM SetBuffer(0x433E0130)는 메시지 큐로 저장 요청을 보내므로, 반환을
플래시 기록 완료로 해석해서 기존 동기식 `vr_io.sync`에 바로 연결하면 안 된다.
완료 통지 또는 동기화 계약을 확인해야 한다.

CSIC 미러 0x29의 128바이트 항목(DSM ID 0x27B0)은 조사 후보일 뿐이다.
정적 배열 설명자에서 참조가 없다는 사실은 다른 용도로 사용하지 않는다는
증거가 아니다. 이를 비어 있는 공간으로 간주해 덮어쓰지 않았다. 현재의
2×512바이트 저장 형식도 이 한 항목에 들어가지 않는다. 기존 저장 서비스의
미러 0x29를 전용하지 않고 중복 NV 등록 행을 활용하는 별도 경로를 구현했다.
이 경로의 크기·배치·완료 처리는 별도 ARM 시험으로 확인하며 실기 검증은 남아 있다.

## 두 상위 잉크 검사 작업의 가상 완료

`vr_native_ink_check_job`은 원본 0x433F6E90, `vr_native_ink_status_job`은
0x433F71FC를 대체한다. 원본의 비동기 하위 요청·지연·재시도 루프에 들어가지
않고 가상 상태를 결과 배열에 공급해 동기적으로 반환한다. 커버 초기화나
소비량을 변경하는 작업이 아니다. 유지보수 칩 통신과 다른 데이터 읽기/쓰기
작업은 이 두 함수의 범위에 포함되지 않는다.

원본 결과 디코더 0x433F823C와 0x433F8584에 오류 없는 기록을 넣어 정상 결과를
확인했다. 칩 검사는 0, 상태 검사는 두 모드 모두 2를 공급한다. 이 값은 논리
`vr_presence_value`의 1과 다른 네이티브 작업 결과 코드다. 반환값 0은 해당 검사
호출의 완료를 뜻한다. 12개의 uint32 선택 배열에서 하나라도 선택된 access
그룹 전체의 결과를 갱신하고 다른 그룹의 결과는 보존한다. NULL 선택 배열은
전체 선택이다. 빈 선택은 아무것도 쓰지 않는다. 원본 slot-access 함수로
연결 시점에 그룹을 확인하며, 커버 번호를 통신 그룹 번호로 가정하지 않는다.

저장 장애가 고정된 경우 선택된 그룹에 오류 코드 5를 공급하고 반환값 1로
상위 작업 진행을 중단한다. 실제 칩으로 복귀하지 않는다. 잘못된 인수는 결과를
쓰지 않고 오류로 처리한다. 호출은 기존 어댑터와 같이 상위 디스패처가 직렬화해야
하며, 실행 중 원본 설정의 access 그룹이 바뀌면 다시 연결해야 한다.

`probe_virtual_ink_jobs.py`는 컴파일한 어댑터와 원본 ARM 호출자를 함께 실행한다.
4,096개 선택 배열 × 세 검사/모드 조합, NULL 선택과 입력/출력 메모리 중첩,
원본 검사 결과 파서 및 복합 검사 호출자, 저장 장애, 커버 세대 변경·재시작을
확인한다. 두 원본 드라이버 행의 모든 콜백 진입점을 감시하며 이 시험 경로에서는
진입이 0회다. 원본 복합 호출자의 16개 선택 패턴에서 선택한 슬롯만 사용 가능
결과를 얻는 것도 확인한다. 이것은 전체 펌웨어의 정품 판정이나 모든 물리 통신
경로 차단을 증명하지 않는다.


## 상위 잉크 데이터 미러 경로

원본 0x43400C3C의 prefix 읽기와 0x434006EC/0x43400DEC/0x43400F18의 쓰기 요청을
가상 RAM 미러 경로로 연결했다. 읽기는 요청한 최대 96개 워드 범위 안에서만
소유자 시리얼·제조사 정보를 복원한다. 쓰기 요청에서는 이미 네이티브 호출자가
갱신한 RAM 미러를 유지하고 소유자 식별자를 공급한다. keep_dirty=0일 때만
해당 슬롯의 96바이트 dirty 표식을 지운다. 오류이면 미러와 dirty 표식을 보존한다.
소비량·세대는 기존 Get/Set/Add/커버 경로가 별도 NV 트랜잭션으로 저장한다.

**이 미러 쓰기 요청은 미해석 메타데이터 전체를 영구 저장하지 않는다.** 그런 필드는
현재 RAM 값으로 유지하며 재부팅 시 재구성·영구 복원 계약은 아직 없다. 유지보수
GF 칩의 데이터 통신, 다른 진단·초기화·보호 명령 전체도 대체한 것이 아니다.
따라서 전체 칩 에뮬레이션 완료나 실기용 펌웨어로 해석하면 안 된다.

`probe_virtual_ink_data.py`는 NV 백엔드를 연결한 코어에서 prefix 읽기 1,164건,
세 쓰기 진입점의 모드 72건, 원본 복구 호출자 12건, 장애·잘못된 인수 처리를
검증한다. 시험 중 ASIC/GF/MR/EPC 통신 진입을 감시하며 해당 진입은 0회다.
