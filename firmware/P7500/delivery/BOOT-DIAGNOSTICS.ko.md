# P7500 부팅 원인 분리 도구

수정 완료 펌웨어가 아닙니다. 실기 부팅은 검증하지 않았습니다. 원본을 같은 칩에 재기록하면 정상 부팅되는 상황에서, 서로 독립적인 변경을 비교하기 위해 만든 진단 후보 생성기입니다. 가상 카트리지·영구 저장 확장 기능은 없습니다. 개인키도 포함하지 않습니다.

## 두 후보의 차이

- `key-only`: 원본의 공개키 두 사본(각 64바이트)만 소유자 공개키로 바꿉니다. CROM 코드와 모든 초기화·저장 정의는 원본 그대로입니다.
- `crom-nop`: 원본 공개키를 유지하고, 명령 한 개를 동등한 명령으로 바꿔 CROM을 재압축합니다. `0x433E002C`의 `MOV R0,R0`를 `ORR R0,R0,#0`으로 바꿔 레지스터·플래그·분기 동작을 유지합니다. 가상화 훅, 드라이버 테이블 교체, NV 확장은 넣지 않습니다.

원본 BIN을 바탕으로 PC에서 원하는 후보를 생성합니다. 칩에 자동으로 기록하지 않습니다. 기존 설치용/런타임 BIN을 입력하면 원본 전체 해시 검사에서 중단합니다.

```sh
python prepare_boot_diagnostic.py key-only original-IC13.BIN original-IC14.BIN key-only-output
python prepare_boot_diagnostic.py crom-nop original-IC13.BIN original-IC14.BIN crom-nop-output
```

원본 IC3.BIN이 물리 IC13, IC4.BIN이 물리 IC14에 대응합니다. 생성된 각 출력 폴더의 IC13.BIN·IC14.BIN은 각각 64MiB입니다. sha256.json으로 기록 후 재독출 파일을 비교할 수 있습니다. 처음의 복구용 원본은 따로 보관합니다. 시험 중 화면/LED가 나오지 않으면 해당 후보는 실패로 기록하고 정상 원본으로 복구합니다. 두 후보 모두 실기 검증 전이며 생산 인쇄용이 아닙니다.

## 결과 해석

재독출 일치가 확인된다는 조건에서:

- key-only만 실패하면 공개키 변경 또는 그와 관련된 초기 검사 경로를 우선 조사합니다.
- crom-nop만 실패하면 CROM 재압축·실제 압축 하드웨어·코드 무결성 경로를 우선 조사합니다.
- 둘 다 부팅되면 기존 가상화 후보의 초기화 훅·콜백 대체·NV 변경 쪽으로 범위를 좁힐 수 있습니다. 각각을 원본에서 다시 분리 시험해야 합니다.
- 결과만으로 정확한 정지 명령이나 모든 후속 동작을 보장하지 않습니다. 화면·전원 LED·부팅 시간과 오류 내용을 구분해 기록합니다.

검증 범위: 명령 동등성 ARM 80개 경우, 압축 후 재해제 전체 비교, 원본 ARM 파서·복사 루프 실행(Huffman ASIC은 시험 대역), 칩 분리/병합 및 원본 외 영역 보존 검사. 전체 부팅·실물 압축 하드웨어는 미검증입니다.
