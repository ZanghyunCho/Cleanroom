# P7500 설치 후보의 부팅 실패 조사

2026-11-04 사용자는 배포한 `EXPERIMENTAL_INSTALLER_IC13.BIN`과 `IC14.BIN`을 기록한 뒤 스위치 동작음만 나고 화면과 전원 버튼 LED가 나오지 않는다고 보고했다. **같은 칩에 원본을 다시 기록하면 정상 부팅**한다고 확인했다. 수정본 기록 후 재독출 파일의 일치는 아직 확인하지 않았다.

현재 후보는 정상 부팅이 검증된 펌웨어가 아니다. 복구된 원본 상태를 유지한다. 원인이 확정되지 않은 상태에서 같은 설치 이미지를 반복 기록하거나 전원 차단·인쇄 시험을 진행하지 않는다.

## 확인한 것과 남은 것

- 배포 ZIP의 해시와 생성 당시의 압축 왕복 비교는 역사적 결과로 보존한다. 이 결과를 정상 부팅 증거로 사용하지 않는다.
- 추가로 원본 ARM 프레임 파서 `0x440998F8` 및 복사 루프 `0x4409997C`를 실행했다. 원본·배포본 모두 프레임 2개를 찾고 두 해제 결과가 Python 해제 결과와 전체 바이트 일치했다. **Huffman ASIC은 Python이 제공하는 토큰으로 대체했다. 실제 압축 하드웨어나 전체 부팅을 재현한 시험이 아니다.**
- 실제 DSM 초기화·플래시 작업자·실행 순서·콜백 계약은 기존 통합 시험에서 일부 대체 구현을 사용했다. 실제 동작을 확인해야 한다. 공개키 변경이 원인이라고 확정한 근거도 없다.
- 같은 칩의 원본 복구 성공은 수정 이미지 또는 기록 결과로 원인 범위를 좁히지만, 실제 실패 지점까지 알려주지는 않는다.

## 재독출 확인

프로그래머로 수정본을 기록했던 두 칩의 읽기 파일이 있다면 다음 읽기 전용 도구로 검사한다. 도구 때문에 다시 수정본을 기록할 필요는 없다.

```sh
python verify_spi_readback.py readback-IC13.bin readback-IC14.bin
```

- `exact_known_image_pair`: 파일 전체가 배포본 또는 원본과 같은지 표시한다.
- `reversed_known_image_pair`: 두 칩 파일 순서가 뒤바뀐 경우를 검출한다.
- `boot_and_modified_code_prefix.matches_known_prefix`: 앞부분의 부트·공개키·수정 CROM 영역만 따로 비교한다. 이후 NV 변경으로 전체 해시가 달라진 경우에도 이 부분은 비교할 수 있다. 다른 모든 코드 영역까지 검증하는 항목은 아니다.
- 미일치만으로 기록 불량이라고 단정하지 않는다. 사용 중 저장 데이터가 바뀌거나 런타임 전환 이미지를 사용했을 수 있다.

원본의 `IC3.BIN`은 물리 IC13, `IC4.BIN`은 물리 IC14에 대응한다. 각 칩 파일 크기는 67,108,864바이트다. 원본을 다시 기록한 뒤 읽은 파일로는 과거 수정본 기록 상태를 확인할 수 없다.

수정본 재독출이 일치하면 실제 부트 로그 또는 부트 단계별 진단으로 진행해야 한다. 아직 수정·부팅 검증을 마친 새 BIN은 없다.
