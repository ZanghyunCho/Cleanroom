# P7500 실험용 SPI 설치 이미지

> **부팅 실패 보고(2026-11-04):** 배포한 설치용 BIN에서 화면·전원 LED가 나오지 않았고, 같은 칩에 원본을 다시 기록하면 정상 부팅됨이 보고되었습니다. 원인은 미확정입니다. 이 후보를 정상 동작 펌웨어로 사용하지 마세요. [진단 기록](BOOT-FAILURE.ko.md)을 참조하세요.

**실물 부팅·인쇄·전원 차단을 통과한 펌웨어가 아닙니다.** ARM 실행·저장 장애
시험과 CROM/칩 분리 검증을 통과한 실험용 후보입니다. 사용자가 SPI 프로그래머로
복구할 수 있다는 조건에서 직접 시험하도록 전달합니다. EFU 업데이트 파일이 아닙니다.

## 파일과 검증 범위

- `EXPERIMENTAL_INSTALLER_IC13.BIN`, `EXPERIMENTAL_INSTALLER_IC14.BIN`: 첨부 원본을
  바탕으로 만든 각각 64MiB의 설치 후보. IC13은 원본 IC3의 2바이트 레인,
  IC14는 원본 IC4의 2바이트 레인입니다. 바이트/워드 스왑을 추가하지 않습니다.
- `installer-rom.patch`, `runtime-rom.patch`, `prepare.py`: 새 SPI 읽기 덤프에 코드
  변경만 적용합니다. 기존 NV·장치별 데이터는 보존합니다. Python 표준 라이브러리만 필요합니다.
- `manifest.json`: SHA-256, 실제 코드 배치, 변경 진입점, 리다이렉트한 하위 호출,
  CROM 왕복 검증 결과. 개인키는 포함하지 않습니다.

12슬롯 소비량·세대, 13개 192바이트 칩 메타데이터, 유지보수 제어 상태를 기록합니다.
유지보수 논리 정보는 장착/정상/100%입니다. 기존 NV 항목의 앞 1,024바이트를
보존하고 뒤의 8,192바이트를 사용합니다. NV 주소 매핑 157개를 유지하며 원래
플래시 서비스가 기록과 가비지 수집을 담당합니다. 그 물리 동작은 아직 실기 미검증입니다.

물리 칩 통신 코드는 상위 가상 경로로 대체합니다. 지원하지 않는 하위 진단 호출은
오류를 반환하며, 원래 ASIC/SPI 인증 프레임을 재현한 것이 아닙니다. 원본 DSM 복원과
물리 NV 작업자는 ARM 시험에서 시험 대역을 사용했습니다. SKU 인식, 초기 프로필과
실제 인쇄 경로의 호환성도 실기에서 확인해야 합니다. Epson 발급 시리얼은 아닙니다.

## SPI 작업 순서

1. 현재 IC13/IC14 전체를 각각 두 번 읽어 두 읽기의 해시가 같은지 확인하고,
   복구용 원본을 따로 보관합니다. 보드 칩 표기·용량·데이터시트의 전압을 확인합니다.
   프린터 전원과 프로그래머 전원을 동시에 연결하지 않습니다.
2. 현재 덤프를 바탕으로 설치 BIN을 만드는 것을 권장합니다.

   ```sh
   python prepare.py install current-IC13.bin current-IC14.bin install-output
   ```

   원본 코드/키 지문이 다르면 중단합니다. 덤프 레인이나 다른 버전을 임의로 맞추지 않습니다.
   첨부 원본과 현재 전체 덤프 해시가 정확히 같을 때는 제공한 설치 BIN을 쓸 수 있습니다.
3. 설치 BIN 두 개를 대응 칩에 기록하고 다시 전체를 읽어 `manifest.json` 또는
   생성된 `sha256.json`의 SHA-256과 비교합니다. 설치용으로 첫 부팅을 시도합니다.
   부팅하지 않거나 오류가 발생하면 복구용 원본으로 되돌리고 증상을 기록합니다.
4. 설치 후 전원을 끄고 두 칩을 다시 읽습니다. **이 읽기 덤프에는 새 가상 상태가
   들어 있을 수 있습니다.** 다음과 같이 일반 실행용 BIN을 만듭니다.

   ```sh
   python prepare.py runtime after-install-IC13.bin after-install-IC14.bin runtime-output
   ```

   코드 영역만 교체하고 설치 이후 상태를 보존합니다. 원본 덤프로 만든 실행용 전체
   이미지를 덮어쓰면 설치한 NV 상태까지 되돌릴 수 있으므로 이 과정을 생략하지 않습니다.
5. `runtime-output/IC13.BIN`, `IC14.BIN`을 대응 칩에 기록·재독출·해시 비교합니다.
   이후의 반복 부팅·인쇄·전원 차단 시험은 **일반 실행용**으로 합니다.

설치용은 기록이 없거나 손상됐을 때 가상 상태를 다시 만들 수 있습니다. 일반 실행용은
이를 하지 않고 오류로 멈춥니다. 설치 이미지를 계속 사용하면서 내구성 시험을 하지 마세요.
읽기/패치 도구는 파일만 만들며 프린터나 프로그래머에 자동으로 쓰지 않습니다.

## 사용자가 수행할 실기 확인

- 최초 부팅: 화면·USB 인식·기존 장치 설정 유지·12색/700ml 논리 프로필 확인
- 일반 실행용 반복 부팅: 소비량·시리얼·메타데이터 유지 확인
- 소량 인쇄 뒤 정상 종료 및 전원 재인가: 소비량이 이전보다 줄지 않는지 확인
- 커버 개폐: 해당 커버의 표시 잔량 10% 미만만 초기화, 정확히 10%와 중복 닫기는 유지
- 전원 차단: 대기 상태부터 시작해 저장/커버 처리 중 차단으로 범위를 늘리고,
  재부팅 후 상태·에러·SPI 읽기 덤프를 보관합니다. 최초 설치 단계의 차단과
  일반 실행 단계의 차단을 구분합니다.

정상 부팅이나 기록 보존을 확인하기 전에는 생산 인쇄에 사용하지 않습니다.
파일 해시와 ARM 시험 통과는 실기 부팅·전원 차단 통과를 의미하지 않습니다.
