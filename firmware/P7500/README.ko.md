# P7500 가상 카트리지 실험용 SPI 이미지

> **부팅 실패 보고(2026-11-04):** 배포한 설치용 BIN에서 화면·전원 LED가 나오지 않았고, 같은 칩에 원본을 다시 기록하면 정상 부팅됨이 보고되었습니다. 원인은 미확정입니다. 이 후보를 정상 동작 펌웨어로 사용하지 마세요. [진단 기록](delivery/BOOT-FAILURE.ko.md)을 참조하세요.

12개 잉크와 유지보수 칩의 전체 192바이트 메타데이터, 소비량, 시리얼 세대를 영구 저장하는 소스와 실험용 BIN 빌더다. **실기 부팅·인쇄·전원 차단은 검증하지 않았다.**

- [SPI 설치 및 실기 시험 절차](delivery/README.ko.md)
- [기존 런타임 구조와 격리 시험](runtime/README.ko.md)
- `runtime/metadata_store.c`: 13개 칩 이미지와 코어 상태를 두 4096바이트 저널에 저장한다.
- `runtime/full_nv.c`: 원본 NV 객체의 기존 1024바이트를 보존하고 소유자 저장 영역 8192바이트를 확장한다.
- `delivery/`: 실제 주소에 배치하는 ARM 페이로드, 시작 훅, 설치/런타임 전환 및 BIN 패키징 도구다.
- `validation/`: 실행한 호스트·ARM 에뮬레이터 검증 결과다. 원본 NV 플래시 작업자와 일부 부팅 초기화는 시험용 대체 구현이다.

`python3 runtime/verify.py`는 빌드, 검증 및 `build/P7500-EXPERIMENTAL-SPI.zip` 생성을 수행한다. 원본 덤프, 도구체인, 공개키 입력이 필요하며 개인키는 패키지에 포함하지 않는다.

설치 후 새로 읽어 낸 두 칩 덤프에서 런타임 BIN을 만들어야 초기화된 영구 데이터가 보존된다. 최초 원본으로 만든 전체 런타임 이미지를 덮어쓰지 않는다. 상세 명령은 설치 안내를 따른다.

유지보수 상위 읽기/저장·모드·제어·준비 상태를 가상화한다. 하위 ASIC/SPI 프로토콜과 모든 진단 명령을 재현하지 않으며 지원하지 않는 진단은 오류를 반환한다. EFU 업데이트 서명 검증은 변경하지 않았다.
