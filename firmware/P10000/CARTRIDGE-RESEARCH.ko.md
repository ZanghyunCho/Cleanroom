# P10000 잉크 카트리지 가상화 조사

사용자 요청은 (1) 미장착 상태에서도 장착으로 동작, (2) Ink End Sensor 정상 보고, (3) 장착 카트리지를 Epson 정품으로 보고하는 것이다. 메인터넌스 패치는 사용자가 적용 성공 및 가용 공간 100% 표시를 보고했다. 아래 내용은 새 잉크 패치의 실기 성공 보고가 아니다.

## 지역별 펌웨어 허용 목록

FM001PA의 `0x43b2c794`가 칩 element `0x25`에서 T코드를 읽고 지역·슬롯·크기 클래스별 표와 비교한다. 원본 ARM 코드를 실행하고 칩 읽기만 명시적인 합성 입력으로 대체해 164개 경우를 검증했다. 검증 상세는 `validation/cartridge-region-results.json`이다.

| 내부 지역 ID | 클래스 0 | 클래스 1 | 클래스 2 |
| --- | --- | --- | --- |
| 1 | T8300–T8309 | T9090–T9099 | T8090–T8099 |
| 2 | T8300–T8309 | T9000–T9009 | T8000–T8009 |
| 3 | T8300–T8309 | T9030–T9039 | T8030–T8039 |
| 4 | T8300–T8309 | T9020–T9029 | T8020–T8029 |

내부 슬롯 순서는 각 계열의 끝자리 `6, 2, 9, 0, 5, 1, 8, 7, 4, 3`이다. 예를 들어 지역 ID 4 / 클래스 2는 다음과 같다.

| 슬롯 | T코드 |
| --- | --- |
| 0 | T8026 |
| 1 | T8022 |
| 2 | T8029 |
| 3 | T8020 |
| 4 | T8025 |
| 5 | T8021 |
| 6 | T8028 |
| 7 | T8027 |
| 8 | T8024 |
| 9 | T8023 |

따라서 T8026 하나를 열 슬롯에 공통으로 사용하면 안 된다. T8026은 원본 코드에서 슬롯 0 / 내부 지역 4에서만 허용되었고, 다른 세 지역에서 같은 입력은 거부되었다. `0xffff` T코드는 모든 지역·슬롯에서 거부되었다.

이 표는 **펌웨어 내부 허용 목록**이다. 국가별 판매 품번의 접두·접미 코드, 색상명, 지역 ID와 실제 국가 이름은 공식 자료로 검증하지 못했다. 공식 `epson.com` HTTPS 접근이 실행 환경 프록시에서 HTTP 403으로 거부됐다. 다른 호스트를 통한 우회는 하지 않았다. 클래스 번호 및 반환되는 용량 원시값을 판매 용량으로 임의 번역하지 않는다. T8026 사용은 지역 4의 표와 일치하지만, 이것만으로 프린터의 저장된 지역 설정을 직접 읽었다고 할 수 없다.

## 확인한 판정 경로

- 지역 검사 `0x43b278cc`: 설정 `0x43b12758(3)`을 읽고 지역 1~4인지 검사한 다음 위 T코드 검색을 호출한다. 다른 지역 카트리지 처리에는 별도 허용 상태와 오류 상태가 있다.
- 비정품 사용 허용 시퀀스 `0x43b1906c`: 상태 7과 9 등을 구분하고 허용 비트·상태를 갱신한다. ‘사용 허용’이 ‘정품 보고’와 동일한 것은 아니다.
- 정품 동의 저장 `0x43b2c610`: `CSIC_sub_SaveConsentNonGenuine` 로그를 내며 교환 이력 및 동의 관련 데이터를 기록한다. 이 함수만 고치는 것은 요청한 정품 판정 자체의 대체가 아니다.
- 캐시된 상태 읽기 `0x43b1e780`: 열 슬롯의 12바이트 상태 레코드를 읽는다. 다른 16바이트 정보 레코드는 `0x43b1e6bc`가 읽는다.
- 가용성 판정 `0x43b1aa94`, 전체 가용성 판정 `0x43b1e46c`: 12바이트 레코드 첫 바이트가 0인 슬롯을 정상으로 취급한다. 명시적인 RAM 시험 입력으로 전체 정상·전체 비정상·각 슬롯 단독 비정상 12개 경우를 원본 ARM 코드에서 확인했다.
- 초기화는 슬롯 첫 상태 바이트를 1로 둔다. 모든 상태를 정상으로 읽도록 바꾸더라도 실제 칩 읽기 시퀀스·지역·정품 정보·부팅 후 갱신까지 가상화했다고 볼 수 없다.
- `0x43b1ab7c` 잉크 검출/잔량 계산에는 소모량·임계값 검사와 칩 상태 읽기가 별도로 있다. 이 경로를 단순히 정상 리턴으로 바꾸면 호출자가 기대하는 출력 필드가 갱신되지 않을 수 있다.

## IES의 미해결 부분

문자열 `PSR IES`가 보이지만, 해당 코드가 사용자가 말한 Ink End Sensor임을 입증하지 못했다. 따라서 그 문자열만으로 패치 지점을 정하지 않았다. 다음 항목을 분리해야 한다.

1. 칩 잉크 소모량에 따른 end 판정.
2. 장착·칩 통신 실패에 따른 사용 불가 판정.
3. 실제 잉크 엔드 센서의 하드웨어 입력 및 그 상위 상태 보고.

현재 시험은 캐시된 상태 및 지역 표의 소비자를 확인한 것이며, 물리 센서 정상 입력의 값·극성·타이밍을 확인한 시험이 아니다.

## 구현 상태와 다음 조건

현재 잉크 가상화 통합 EFU는 생성하지 않았다. 앞서 성공한 메인터넌스 EFU와 다운로드 파일은 그대로 유지했다. 장착 판정만 정상으로 만드는 단편 패치를 설치본으로 내지 않는다. 통합 후보에는 다음 근거가 필요하다.

- 지역 설정에 맞는 열 슬롯 T코드와 크기/정품/지역 상태를 일관되게 생성.
- 칩이 없어도 읽기·쓰기·재장착 시퀀스가 초기화 실패 또는 시간 초과로 되돌리지 않는지 확인.
- 실제 IES 입력과 보고 상태의 대응을 특정하고, 출력 구조·콜백·완료 통지를 보존.
- 기존 메인터넌스 8바이트 패치를 함께 보존한 상태로 재압축·원본 ARM 복원 시험.

물리적 잉크 공급은 상태 보고와 별개다. 첫 실기 시험은 인쇄·클리닝 없이 장착/정품/센서 상태 화면에서 진행해야 한다.
