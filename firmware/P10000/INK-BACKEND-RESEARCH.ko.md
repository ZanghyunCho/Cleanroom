# 잉크 미장착·정품·잉크 엔드 경로 후속 연구

V2 정상 동작은 사용자 보고로 기록했다. 이 문서는 이후의 원본 ARM 실행 및 시험용 백엔드 결과다. 이 문서의 전반부는 개별 경로/백엔드 시험이며, 이후 [V3 통합 후보](INK-VIRTUAL-V3.ko.md)를 생성했다. 기존 V2 파일은 보존했다.

## 정상/잉크 엔드 입력

원본 잉크 엔드 판정 `0x43b19804`는 `0x43b3f3a4`에서 비트 마스크를 받는다. 다른 호출자는 원본 진단 로그에서 이를 `ils`로 표시한다. PSR의 IES 문자열과는 다른 경로다. 실제 칩 장착 CO 조회는 별도 `0x43b24f2c` 경로다.

`0x43b3f3a4`는 디바운스 상태 레코드의 16비트 값 12개를 읽고, 값이 1인 채널의 비트를 켠다. 활성 잉크 슬롯 10개가 엔드 판정의 대상이다. 이 12비트에 유지보수 슬롯이 포함된다는 이전 추정은 철회한다. 채널 수만으로 그런 결론을 낼 근거가 없으며, 11·12번째 채널의 물리 용도는 확인하지 못했다.

원본 캐시 기반 가용 상태와 near-end 필드를 정상으로 둔 시험에서:

- `ils` 마스크 0은 추가 엔드 오류를 발생시키지 않는다.
- 활성 슬롯의 비트가 켜지면 원본 코드가 그 슬롯의 상태를 6으로 바꾸고 오류 코드 `0x25`를 게시한다.
- 후보 변경 `mov r0,#0; bx lr`를 조회 함수 첫 8바이트에 적용하면, 같은 원본 호출자에서 모든 시험 입력이 엔드 오류 없이 처리된다.
- 원시 디바운스 상태 메모리는 변경하지 않았다.

원본과 후보를 각각 15개 마스크로 시험했다. 이 결과는 **펌웨어가 소비하는 디바운스 입력의 정상값**을 확인한 것이다. 전기적 핀 극성, 실제 하드웨어 단선·공급 부족, 이 조회 함수를 거치지 않는 모든 직접 관찰자를 검증한 결과는 아니다.

시험 중 원본 상태 6 분기에서 반환용 결과 배열 일부가 내부 임시 배열로 덮어써지는 현상도 관찰했다. 따라서 원본 오류 사례를 반환 배열만으로 판정하지 않고 실제 캐시 상태와 오류 게시 호출을 함께 확인했다.

재현: `python firmware/P10000/probe_ink_sensor_and_genuine.py`

## 정품 보고와 실제 인증의 구분

원본 16바이트 정보 레코드의 `+4` 반워드가 1이면 송신자 `0x43b1edd4`가 메시지 `+0x5a`에 해당 슬롯 비트를 넣는다. 수신자 `0x43c49658`는 이 값을 JCT 상태 `+0x34` 및 누적 이력 `+0x58`에 반영한다. 원본 로그는 이 정보를 정품/비정품 정보로 표시한다.

모든 비트 0, 각 슬롯 단독 1, 열 슬롯 모두 1의 12개 경우에서 원본 송신자와 수신자를 모두 실행했다. 따라서 비정품 사용을 허용하는 처리와 비정품 비트를 보고하지 않는 처리가 다르다는 점을 코드 실행으로 확인했다. 누적 이력도 있으므로 출력 메시지만 한 번 고쳐서는 ‘항상 정품’이 되지 않을 수 있다.

이 시험은 상태 보고 경로에 대한 것이다. 실제 Epson 칩의 암호 인증, UID 또는 제조사 서명 재현을 입증하지 않는다.

## 가상 칩 단어 백엔드

`prototypes/ink_chip_model.c`를 ARMv5TE 정수 코드로 컴파일했다. 열 슬롯의 각 84개 16비트 단어를 처리한다. 데이터 컨텍스트는 1,680바이트다. 실제 ASIC을 사용하는 원본 단어 읽기/쓰기 경계만 컴파일된 ARM 백엔드로 연결하고, 원본 필드 해독기 `0x43b2c0ec`와 쓰기 함수 `0x43b2e65c`는 그대로 실행했다. 단순 성공 반환 함수로 대체하지 않았다.

원본 필드 매핑 표에는 77개 유효 필드와 마스크 0인 예약 항목 `0x4d`가 있다. 예약 항목은 유효 필드 시험에서 제외했다. 유효 ID별로 단어 주소와 마스크를 보고서에 기록했다.

- 네 내부 지역의 클래스 2 품번을 슬롯별로 초기화하고 원본 해독기로 재조회했다.
- 용량 필드 `0x24`의 시험용 원시값 3400은 원본 용량 변환에서 680으로 변환되는 값이다. 아직 모든 색상·모델에 대한 물리 용량 정책으로 확정하지 않았다.
- 원본 해독기를 통한 읽기·품번 확인 2,390개를 통과했다.
- 원본 쓰기 함수와 해독기를 통한 쓰기/재조회 2,310개를 통과했다.
- 원본 쓰기가 붙이는 `0x8000` 마커와 대상 마스크 밖 비트의 보존을 확인했다.
- 잘못된 슬롯·주소·초과 값은 상태 변경 없이 거부했다. 출력 버퍼 경계도 확인했다.

재현: `python firmware/P10000/probe_virtual_ink_model.py`

**현재 컨텍스트 주소 `0x43080000`은 에뮬레이터 시험 공간이다. 프린터용으로 예약된 RAM 주소가 아니다.** 이 코드를 그 주소 그대로 EFU에 넣으면 안 된다. 상태는 휘발성이며 영구 저장을 구현하지 않았다. 원본 전체 칩 메타데이터의 의미와 제조사 인증도 모두 검증한 것은 아니다.

## V3 통합 결과와 한계

[V3 통합 후보](INK-VIRTUAL-V3.ko.md)는 기존 커버 처리 함수의 제거되는 공간에 1,684바이트 상태(단어 1,680 + 초기화 표식 4)를 배치했다. 기본 프로토타입 주소와 다르다. 기존 MPU 초기화의 데이터 접근 권한, 남아 있는 직접 분기 및 상태 영역을 가리키는 외부 리터럴을 검사했다.

원본 미장착 조회/요청 완료, 원본 정품 송신자→JCT 수신자, 원본 상태 통지, ILS를 소비하는 엔드 판정과 상위 IKS 검출 요청을 통합 코드와 함께 실행했다. 실제 통신 대신 단순 성공 반환을 넣은 방식이 아니라 가상 단어 백엔드가 원본 필드 읽기/쓰기 요청을 처리한다. OS IPC 및 날짜/NV 정리 호출에는 명시적인 시험 경계를 사용했으며, 실제 저장을 검증한 것은 아니다.

상태는 재부팅 시 초기화된다. 칩 템플릿은 명시적인 가상 일련번호를 사용하며, 전체 공장 메타데이터·암호 인증을 재현하지 않는다. V3의 실제 부팅, 미장착 동작, 실제 IES/ILS 배선, 인쇄·클리닝·잉크 공급은 미검증이다.
